# Gate (manual 29.20)

**Family:** dynamics
**Note status:** dump checked

## Summary

A downward expander with a floor: when the detector level is under the threshold, the gain is brought down to the Floor value, and when it is over, the signal passes. Hysteresis (Return), Hold, Attack, Release and a short Lookahead keep it from chattering or clicking. It cleans noise between sounds, shortens tails, and, with the side-chain, imposes the rhythm of one signal onto another. Flip reverses it, so the device passes only quiet signals (a ducker).

## Signal flow

Shared parts: [common.md](common.md) (side-chain section).

```text
input ─┬────────────► lookahead delay (0 / 1 / 10 ms) [manual] ─► gain element ─► output
       │                                                              ▲
       └─► detector input = own input, or external side-chain × Gain blended by side-chain Dry/Wet [manual]
             └─► side-chain EQ (optional) [manual]
                   └─► level detector (type: [measure])
                         └─► open/close logic: open at Threshold, close at Threshold − Return, Flip inverts [manual]
                               └─► hold timer, then attack (closed → open) and release (open → closed) toward Floor [manual]
```

- There is no dry/wet, no output gain and no ratio or knee on this device [source: 2].
- The detector is ahead of the lookahead delay, so the gate can open before the delayed transient arrives [manual: lookahead reasoning; inferred for the tap].

## Behaviour

**Open and close levels.** The gate opens when the detector level rises over Threshold, and it closes when the level falls under Threshold − Return [manual] [inferred: hysteresis form]. With Return 0 dB, a single threshold [inferred]. A source describes Return as moving the gate-on threshold below the gate-off one [source: 2]; the manual has the pairing as "difference between the level that opens and the level that closes", which is the same quantity. I read it as open = Threshold, close = Threshold − Return [inferred] [measure] (it could also be open = Threshold + something, depending on which line the display calls Threshold).

**State machine.** Closed → (level over open threshold) → opening for Attack time → open. Open → (level under close threshold) → Hold period → closing over Release time → closed [manual]. A re-trigger during release goes back to Attack from the current gain [inferred] [measure]. Hold: a competing description ("the minimum time the gate stays closed") exists in a Sound On Sound article; the manual's description (starts when the level drops under the threshold) is used here [manual] [source: 2] conflict.

**Floor.** The gain when closed is Floor (in dB) [manual]. Opening and closing move the gain between Floor and 0 dB; whether the Attack and Release curves are linear in gain, linear in dB or exponential is [measure].

**Flip.** The signal passes only when the level is under the threshold [manual]. In Flip, Release is the speed at which the flipped signal rises when gating starts, and Attack the speed at which it falls when gating ends [source: 2] (so Attack and Release keep their meaning for the inverse gain, [inferred]). With Floor at −inf, a normal gate and a flipped one with identical settings, in parallel, sum to the input [source: 2] — this shows that the two gains are complementary, so the sum is exact [inferred] [measure].

**Lookahead.** Delays the audio by 0, 1 or 10 ms [manual]; the panel and the API show the middle step as 1.5 ms [dump 12.4.6], which fits the 1.5 ms (72-sample) figure below. The device reports latency equal to the lookahead [source: 5, second-hand]. The Live help centre page also lists a fixed latency figure for the Gate (72 samples, 1.5 ms) that may belong to an older version; it is second-hand and [measure].

**Detector.** The manual does not say whether it is peak or RMS; a peak or a very fast envelope is the usual choice [inferred] [measure]. Stereo: one detector for both channels so the image does not shift [inferred] [measure].

**Display.** Input in light grey, output in dark grey with a white outline; the threshold line is blue and the Return line is orange [manual]. In Listen mode the side-chain signal is drawn in green [manual].

**Side-chain.** As in [common.md](common.md). Used for rhythmic gating: a held pad opened by a drum loop [manual].

## Edge cases

- Floor 0 dB: the device does nothing to the signal [manual].
- Floor −inf: a closed gate is silent [manual].
- Threshold at its minimum: the gate is always open (without Flip); with Flip always closed [inferred].
- Hold 0 and Return 0 with a signal at the threshold: chatter [source: 4]; Return and Hold reduce it [manual].
- Attack minimum with a Floor of −inf: the gain steps from silence to full level in less than a cycle of low frequencies: clicks [manual].
- Lookahead 0 with a fast transient and a slow Attack: the transient's start is attenuated [inferred].
- Changing Lookahead while playing: changes delay; the host's delay compensation changes [source: 5] [inferred]; clicks [measure].
- Flip with Floor at −inf: complementary to the normal gate [source: 2].
- Mono input, silence (the gate is closed or stays in its state), denormals: [measure].

## Measurement plan

1. ~~**Ranges and defaults.**~~ Answered by the dump and the saved set [dump 12.4.6] [als 12.4.6], including the side-chain controls.
2. **Open and close levels.** A sine whose level ramps slowly up and then down (0.5 dB/s) across the threshold with Attack and Release minimum, Hold 0, Floor −inf, Lookahead 0. Record the levels at which the gate opens and closes with Return 0, 6, 12 dB and the maximum; compare with Threshold and Threshold − Return. Check the display lines against the measured levels.
3. **Floor and gain law.** Closed gate with Floor −inf, −12, −6, 0: read the output level; read the attenuation curve of a release from open to closed (output / input) with Release 100 ms and 1 s: linear in dB? exponential?
4. **Attack and Release times.** A tone burst over the threshold with a long silence between: read the gate's opening (Attack 0.1, 1, 10, 100 ms) and closing (Release 10, 100, 1000 ms), from the ratio of output to input; report 10 %–90 % and 63 % times.
5. **Hold.** A burst followed by a drop under the threshold; Hold 0, 50, 200, 1000 ms with Release minimum: measure the time between the level drop and the start of the gain fall; check against the manual's definition, and against the "stays closed" reading by re-triggering bursts at a short interval.
6. **Re-trigger during release.** Two bursts separated by less than Release; check the gain curve of the second attack (restart from the current gain or from the floor).
7. **Flip.** Repeat tests 2, 3 and 4 with Flip on; check which of Attack and Release applies to which transition; run the parallel normal-plus-flipped null test with Floor −inf (expected: sum = input).
8. **Lookahead and latency.** Impulses at Lookahead 0, 1, 10 ms; read the delay at 44.1 and 48 kHz; compare with the title bar's tooltip; check that the transient passes at full level when Attack is minimal. Look for any latency when Lookahead is 0 (the help centre's 72-sample figure).
9. **Detector type.** Tone bursts of 0.5, 1, 5, 20 ms with the same peak level around the threshold: does the open decision depend on the burst length (RMS) or only the peak? Test with a signal with a high crest factor (an impulse train).
10. **Stereo.** One channel loud, the other silent; different levels per channel; check the gain applied to the silent channel.
11. **Side-chain.** External source, Gain range, Dry/Wet 0 / 50 / 100 %, EQ filter types, frequency, Q and gain ranges (noise through each, Listen on), as for Compressor; check the display colour in Listen mode.
12. **Sample rates.** Repeat test 4 at 44.1, 48 and 96 kHz.

## Implementation notes

- **Building blocks:** biquad filters for the side-chain EQ, one-pole envelopes, dB conversions.
- **Also needed:** a hysteresis state machine with hold, a fixed lookahead delay that reports its latency, a peak detector and a level display.
- If the detector is shared with Compressor and Glue Compressor, one detector (peak, RMS, side-chain filter) can serve all three.
- The key input is the same side-chain primitive Compressor uses ([common.md](common.md) › Side-chain section).
- `.als` import: the element is `Gate` [als 12.4.6]. Parameter elements in the set saved from Live 12.4.6 [als 12.4.6], each holding a `Manual` value: `On` (bool), `Threshold` (linear gain, 0.251 = −12 dB), `Attack` (ms), `Hold` (ms), `Release` (ms), `Return` (dB), `Gain` (this is the Floor, in dB: −40), `SideChain/OnOff` (bool), `SideChain/RoutedInput/Volume` (linear gain, the side-chain Gain), `SideChain/DryWet` (fraction), `SideListen` (bool), `SideChainEq/On` (bool), `SideChainEq/Mode` (index 0 – 5, the type list above), `SideChainEq/Freq` (Hz), `SideChainEq/Q`, `SideChainEq/Gain` (dB), `FlipMode` (0 Normal, 1 Flip) and `LookAhead` (index 0 – 2 into 0, 1.5, 10 ms; the loaded value is 1). The stored units are therefore physical (ms, dB) except the two linear-gain fields.
