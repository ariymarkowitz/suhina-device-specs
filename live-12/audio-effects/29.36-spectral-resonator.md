# Spectral Resonator (manual 29.36)

**Family:** reverb and resonance
**Note status:** dump checked, partly measured (top100 runs, [Measured](#measured))

## Summary

A frequency-domain resonator. The input is analysed with an FFT, and a set of tuned resonant
partials (a harmonic or stretched series on a root pitch) is used to emphasise and sustain
matching parts of its spectrum, which is turned back into audio. The root pitch is fixed
(Internal mode) or set by incoming MIDI notes (MIDI mode, mono or up to 16 voices), so it works
like a vocoder, a tuned reverb, a drone generator or a "tonal drum" maker. Four modulation
modes, unison, damping and a spectrogram complete it [manual, source: 2, 3].

## Signal flow

```text
in --> Input Send (gain) --> Shift (spectrum transposed by +-48 st) --> FFT analysis
        |                                                                  |
        |      resonant partial bank: Harmonics, Stretch, Decay, HF Damp, LF Damp,
        |      pitch from Freq (Internal) or MIDI voices, Quantize, Unison, modulation (Chorus / Wander / Granular)
        |                                                                  v
        |                                              spectral resonance --> inverse FFT --> limiter --+
dry ------------------------------------------------------------------------------ Dry/Wet ------------+--> out
```

- Shift acts on the signal fed into the device, not on the resonator's own spectrum [manual].
- Input Send is a gain on the signal that is processed; a built-in limiter keeps the wet signal
  from clipping and an LED beside the knob shows it working [manual]. The limiter is therefore
  after the resonator [inferred] (it could also precede the FFT; [measure]).
- The spectrogram shows dry (yellow) and wet (blue) signals; Dry/Wet changes how prominent each
  is [manual].
- Order of Shift versus Input Send is [inferred].

## Behaviour

- **Method.** A short-time Fourier transform: the input is windowed, transformed, its spectrum
  is processed, and the result is transformed back and overlap-added [source: 6]. The FFT size,
  hop, window shape and whether it is a fixed size are [measure].
- **Resonant partials.** A comb of narrow peaks at `f0 * h(k)` for partial number k. Only input
  energy near a peak is kept and sustained, with each peak's energy persisting for a
  time set by Decay: a per-bin recursive decay of the magnitude is the most likely design
  [inferred]. A frequency must be in the input for the output to contain it; a single played
  note brings out the others in the background, similar to a sitar [source: 6]. Measured: with noise in, every
  partial comes out as a steady sinusoid at the exact partial frequency (its line is narrower than 0.6 Hz at
  Decay 222 ms, where a linear resonator with that T60 would be about 10 Hz wide), and the impulse response
  decays at exactly the Decay time (Measured › Partials, Decay) [measured 12.4.6].
- **Partial positions.** Stretch moves the series from harmonic: positive widens the spacing,
  negative narrows it; at +100 % only odd harmonics are left. One formula that satisfies these
  endpoints is partial `n` at `f0 * (1 + (n - 1)(1 + s))` for `s` in −1 to 1, giving harmonic at
  0 and odd harmonics at 1 [inferred]. Measured: this formula holds at Stretch −50, 0, +50 and +100 % to within
  0.07 Hz for every partial up to 19.9 kHz, and at −100 % all partials sit on f0 (a single line)
  (Measured › Partials) [measured 12.4.6].
- **Harmonics.** The number of partials in use (1 to 256 in the wrapper) [source: 2]; with
  polyphony the number is divided among voices [manual].
- **HF Damp and LF Damp.** Extra attenuation or faster decay of the upper or lower partials,
  with the split placed relative to the fundamental [manual, inferred]; slopes [measure].
- **Shift.** Moves the input spectrum up or down by ±48 semitones before resonance, by bin
  remapping or a phase-vocoder shift [manual, inferred]. A formant-preserving shift is not
  stated [measure].
- **Internal mode.** One fundamental, from Freq (Hz or pitch) [manual]. With Use Current Scale
  the fundamental is relative to the scale [manual].
- **MIDI mode.** Notes from the chosen MIDI track set the fundamentals. Mono: the last note
  (priority is not stated [measure]) with Glide; Poly: up to 16 voices [manual]; wrapper steps
  2, 4, 8 and 16 [source: 3]. MIDI Gate On: no resonance without a held note; Off (mono only):
  the device keeps responding to audio at the last pitch [manual]. Pitch bend within PB, MPE
  supported [manual]. Transp. adds to the note [manual].
- **Modulation modes** [manual]:
  - None: no modulation.
  - Chorus: a triangle wave modulates each partial; at Mod Rate 0 only the amplitudes
    are modulated. Partials use different frequencies [source: 2].
  - Wander: random sawtooth waveforms (ramps to random levels at random intervals [source: 2])
    modulate each partial.
  - Granular: random exponential decay envelopes on the partial amplitudes; grains start at
    irregular intervals, Mod Rate sets the density. Live 12.2: grains start as soon as the
    mode is switched on, and a grain no longer always contains four sinusoids; partial phases
    are randomly distributed so unison and modulation sound even [source: 4].
- **Unison.** Duplicates the partials N times with detune set by Uni. Amt [manual]; each voice
  gets its own random modulation in Wander and Granular [manual].
- **Limiter.** Built-in limiter on the wet signal [manual].
- **CPU.** More harmonics, voices and unison cost more [manual]. The Live 11.0.5 release cut
  CPU by about 15 % (about 20 % with few audible partials) and made the spectrogram much cheaper
  [source: 4].
- **Latency.** An FFT device has latency of at least the analysis window; whether it reports
  it and whether the dry path is compensated is [measure]. Measured: at Dry/Wet 100 % the response to an
  impulse begins 546 samples (12.4 ms) before the impulse in the render, so Live compensates a reported latency
  by shifting the device's output earlier; its value is not read from this (Measured › Things that affect how to read the renders) [measured 12.4.6].
- **Spectrogram.** Computed from the dry and wet signals; a display-only feature, not part of
  the sound [manual].

## Edge cases

- Mono mode, MIDI Gate on, no notes: silence [manual]; MIDI Gate off, no notes: audio
  continues to resonate at the last pitch [manual, inferred].
- Poly mode: MIDI Gate is forced on [manual].
- Freq at 20 Hz with 256 harmonics: partial spacing is smaller than the FFT bin spacing;
  partials merge, so a high Harmonics count is useful only above a pitch-dependent limit
  [inferred].
- Partials above Nyquist or above the highest FFT bin are dropped [inferred]. Measured: the highest partial
  made is below 20 kHz (19.91 kHz is present, 20.02 kHz is not), a little under Nyquist (22.05 kHz); at Freq 55 Hz
  all 256 Harmonics are present, up to 14.08 kHz (Measured › Partials) [measured 12.4.6].
- Stretch at +100 %: only odd harmonics [manual]; at −100 % the spacing is zero: all partials are on Freq,
  one line [measured 12.4.6].
- Shift at ±48: spectrum moves out of range; content is lost [inferred].
- Pitch bend 0: no bend [manual].
- Scale awareness on with no scale: chromatic [manual]. Tuning system: integer indices
  [manual].
- Decay at maximum: long tails; the device must stay stable and not accumulate DC or
  denormals [inferred].
- Silence in: the resonance rings out and fades; whether Granular keeps producing grains with
  no input is [measure].
- Sample rate change or buffer size change: FFT size may be fixed in samples, so tuning of the
  partial positions in Hz must not change [inferred].
- Transport or tempo: no tempo dependence is stated [manual].

## Measured

[measured 12.4.6] Behaviour runs at 44.1 kHz in Live 12.4.6 (`measurements/29.36-spectral-resonator/`:
`spectral-resonator-partials`, `spectral-resonator-decay`, in the top100 set), Internal mode, Dry/Wet 100 %,
Freq 110 Hz, Stretch 0, Harmonics 256, Decay 222 ms, HF and LF Damp 0, Shift 0, Unison 1, Input Send 0 dB,
modulation None, except the one under test. The partials are read from the white-noise segment of the
render (4 s, independent noise in L and R, the left channel; first 0.3 s skipped) as an averaged periodogram
with 32768 points (1.35 Hz) and, for line shapes, one periodogram of the whole 3.7 s; positions are
parabolic interpolations. Decay times are read from the impulse response (10 s after the impulse) as the
Schroeder-curve fit between -5 and -35 dB (T30, extrapolated to 60 dB) of the whole response and of
single partials isolated with a Gaussian filter about ±30 Hz wide. These are observations, not a model.

### Things that affect how to read the renders

- Live compensates the device's latency: in every render the response to the impulse begins 546 samples
  (12.4 ms) before the impulse, and is strongest in the 64 samples around the impulse itself. The output is then not
  causal in the render, and the delay of the wet path cannot be read directly [measured 12.4.6]. The device
  therefore reports a latency [inferred]; its value was not read.
- The harness's noise response (`response.noise_db`, 1/6 octave) is far too coarse for a comb of lines
  55 to 880 Hz apart, and was not used [measured 12.4.6].
- Decay 40 ms in the decay run is the dump's 40.1 ms; the default case of each run is Freq 110 Hz, Decay 222 ms
  (the two runs have separate renders). No two renders are bit-identical, apart from the bypass references [measured 12.4.6].
- The side peaks about 25 dB under a line, 9.5 to 12 Hz away (seen near single lines at Stretch -100 % and Freq
  880 Hz), were not examined [measured 12.4.6].

### Partials

Harmonics 256, Decay 222 ms. A partial counts as present when it stands 20 dB or more above the median of the
spectrum around it.

| Case | Formula tested (Hz) | Partials present | Highest present | Largest deviation from the formula |
|---|---|---|---|---|
| Freq 55 Hz | 55 n | 256 (all) | 14 080 Hz | 0.055 Hz |
| Freq 110 Hz, Stretch 0 (default) | 110 n | 181 | 19 910 Hz | 0.028 Hz |
| Freq 220 Hz | 220 n | 90 | 19 800 Hz | 0.065 Hz |
| Freq 880 Hz | 880 n | 22 | 19 360 Hz | 0.058 Hz |
| Stretch -100 % | 110 for every n | 1 line | 110 Hz | 0.022 Hz |
| Stretch -50 % | 110 + 55 (n - 1) | 256 (all) | 14 135 Hz | 0.029 Hz |
| Stretch +50 % | 110 + 165 (n - 1) | 121 | 19 910 Hz | 0.024 Hz |
| Stretch +100 % | 110 + 220 (n - 1), the odd harmonics | 91 | 19 910 Hz | 0.027 Hz |

- Partial n of the series sits at Freq × (1 + (n − 1)(1 + Stretch/100)) at all the Stretch values tried: the
  note's formula holds, with no further non-linearity, and the deviations are the precision of the reading
  [measured 12.4.6].
- Stretch -100 % collapses all the partials onto Freq: one line at 110 Hz [measured 12.4.6]. -50 % makes the
  spacing 55 Hz, which for Freq 110 Hz is the series 110, 165, 220, ..., i.e. every multiple of 55 Hz from the
  second [measured 12.4.6].
- Nothing is made above about 20 kHz: every series stops at its last partial below 20 kHz (the next ones, at 20.02,
  20.24, 20.08 and 20.13 kHz in the cases above, are absent). Harmonics 256 is only the limit when the spacing is small: at
  Freq 55 Hz (256 partials to 14.08 kHz) and at Stretch -50 % [measured 12.4.6].
- Partials are of nearly equal level over the whole series: the first, the median and the last partial of the
  default comb stand 36.7, 33.7 and 37.5 dB over the surrounding spectrum (HF and LF Damp 0) [measured 12.4.6].
  Between two lines of the default comb (110 Hz apart) the spectrum is about 35 dB lower than the lines.
- With noise in, each partial is a steady sinusoid at the partial frequency to 0.003 Hz (880.001 and
  1760.003 Hz in the Freq 880 case) and the line is as narrow as the analysis allows: -3 dB full width about
  0.4 Hz in a 3.7 s periodogram. A linear resonator with a 222 ms T60 fed with noise would give lines about
  10 Hz wide, so the device holds each partial rather than ringing like a filter [measured 12.4.6, the
  interpretation inferred].

### Decay

Freq 110 Hz, Harmonics 256, HF and LF Damp 0. Impulse response, both channels identical.

| Decay | T30 of the whole response | T30 of single partials (110, 330, 1100, 3300, 9900 Hz) | EDT (0 to -10 dB) | Energy of the response, re a unit impulse |
|---|---|---|---|---|
| 40.1 ms | 0.044 s | 0.040 to 0.046 s | 0.086 s | -9.1 dB |
| 222 ms (default) | 0.222 s | 0.221 s | 0.226 s | -1.0 dB |
| 313 ms | 0.313 s | 0.313 s | 0.317 s | +0.7 dB |
| 1.06 s | 1.059 s | 1.059 s | 1.061 s | +6.4 dB |
| 2.5 s | 2.497 s | 2.497 s | 2.501 s | +10.2 dB |
| 8.44 s | 8.43 s | 8.43 s | 8.44 s | +15.5 dB |

- The Decay display is the T60 of every partial: from 222 ms up T30 is 0.221, 0.313, 1.059, 2.497 and 8.43 s for
  0.222, 0.313, 1.06, 2.5 and 8.44 s, within 0.5 %, and the same at 110 Hz and 9.9 kHz; the decay is a straight
  line in dB (EDT equals T30). At 40 ms the fit is limited by the 5 ms resolution of the partial filter
  (0.040 to 0.046 s per partial, 0.044 s overall) [measured 12.4.6].
- With HF and LF Damp at 0 there is no frequency dependence of the decay between 110 Hz and 9.9 kHz [measured 12.4.6].
- The response to the impulse is a train of pulses 9.09 ms apart (1/110 Hz; spacings 9.02 to 9.12 ms), each a
  burst a few samples wide, as the comb of lines at multiples of 110 Hz requires; the response starts 546 samples
  before the impulse (see above) and decays at the Decay time [measured 12.4.6].
- The energy of the response grows with Decay: 24.6 dB from 40.1 ms to 8.44 s, against 23.2 dB if it were
  proportional to Decay, so the level of a held noise is not normalised away (the pulses also get taller: peak 0.087 at 40.1 ms, 0.145 at 222 ms,
  0.249 at 8.44 s) [measured 12.4.6]. The response is the same sample for sample in the left and right channels
  [measured 12.4.6].

   Decay; check how HF and LF Damp change T60 per partial.

   (Measured › Decay). Still open: HF and LF Damp per partial; Decay between 8.44 and 20 s.
5. **Shift.** Sine sweep in; read the output frequency versus Shift; test content near
   the ends; check whether formants move.
6. **FFT and latency.** Impulse at Dry/Wet 100 % and 0 %; read the delay of the output peak;
   test a sine to see the bin spacing and the window (frequency resolution at several pitches);
   check the dependence on the sample rate.
   Partly (from the partials and decay renders): at Dry/Wet 100 % the response starts 546 samples before the impulse,
   which is Live's latency compensation (Measured › Things that affect how to read the renders). Still open: the
   reported latency, Dry/Wet 0 %, the window and bin spacing, other sample rates.
7. **MIDI mono.** Play legato and staccato notes from a MIDI track with MIDI Gate on and off,
   Glide at several values; read the pitch trajectory; note priority with overlapping notes;
   PB range and MPE.
8. **MIDI poly.** Chords with Polyphony 2, 4, 8, 16: voice stealing rule, the harmonic split
   per voice.
9. **Modulation.** For each mode, noise or sine in at Mod Rate low, mid, high and Pch. Mod
   0, 2, 4 st: read the amplitude and pitch modulation depth and rate; the Granular grain
   density and envelope; confirm the unit of Mod Rate.
10. **Unison.** Sine in; read the detune of unison voices versus Uni. Amt and the number of
    voices; confirm the wrapper's 1 – 8 range against the UI (the panel shows 1, 2, 4, 8 [dump 12.4.6]).
11. **Scale and tuning.** With a clip scale and with a loaded tuning, read Freq or SD Shift,
    Transp. ranges and the frequency of Quantize-snapped harmonics.
12. **Limiter.** A loud burst at high Input Send: threshold, lookahead, release; LED.
13. **Dry/Wet.** Sine at 50 %; level versus ends; dry delay compensation.

## Implementation notes

- **Building blocks:** an LFO (modulation sources: triangle for Chorus, random for Wander),
  parameter smoothing (and Glide), dB conversions, biquad damping filters (if any parts run in
  the time domain), a DC blocker. A windowed STFT is the base for the FFT engine; Signalsmith
  Linear (MIT) has a Kaiser-windowed one.
- **Missing:** a resonant-partial synthesiser or spectral-mask processor (partial bank, per-bin
  recursive decay, Stretch law, damping curves); a MIDI voice allocator and a mono/poly
  note priority with Glide and pitch-bend ranges (shared with MIDI-sidechained effects such as
  Corpus); scale and tuning-system quantisers (shared with Resonators); a unison and
  random-phase generator; a limiter; a spectrogram view for the UI (display only).
- **MIDI input to an effect.** A MIDI side-chain must reach the effect from another track at
  block level ([common.md](common.md) › MIDI side-chain); the same holds for Corpus.
- **Hard to match:** the FFT size, windowing and the exact way partials are synthesised from the
  input spectrum, and every default; match controls and ranges first.
- **Parameter set for import:** Pitch Mode, Mono/Poly, Polyphony, MIDI Gate, Glide, PB, Freq,
  frequency dial mode, Use Current Scale, Transp. (or SD Shift), Stretch, Shift, Decay, HF
  and LF Damp, modulation mode, Mod Rate, Pch. Mod, Harmonics, Quantize, Input Send, Unison,
  Uni. Amt, Dry/Wet, spectrogram toggle (UI).
- **.als element:** `Transmute` [dump 12.4.6] (the device's internal name; its display name is Spectral Resonator). Parameter elements [als 12.4.6] (stored units where they differ from the display): `On`, `MidiPitch_Transpose`, `MidiPitch_TransposeScaleDegrees`, `MidiPitch_Glide`, `PartialFrequencies_FrequencyHz` (Hz, 110), `PartialFrequencies_FrequencyNote` (45), `PartialFrequencies_Shift`, `PartialFrequencies_PartialStretch` (stored 0 = 0 %), `PartialFrequencies_QuantizeToScaleOrTuning`, `DecayDamping_DecayTime` (seconds, 0.222), `DecayDamping_HighFreqDamp`, `DecayDamping_LowFreqDamp`, `Modulation_ModRate` (0.1 = 10 %), `Modulation_PitchModAmount`, `Global_NumHarmonics` (256), `Global_Unison` (index, 0 = 1 voice), `Global_UnisonAmount` (0.1 = 10 %), `Global_InputSend` (dB, 0), `Global_DryWet` (1 = 100 %), `Global_UseScale`. Not API parameters but stored as plain values [als 12.4.6]: `Global_PitchMode` (0 = Internal), `MidiPitch_MonoPolyMode` (0 = Mono), `MidiPitch_Polyphony` (3, see Controls), `MidiPitch_MidiGate` (0 = Off), `MidiPitch_PitchBendRange` (semitones, 2), `PartialFrequencies_FrequencyDialMode` (0 = Hertz), `Modulation_ModMode` (0 = None) (the meanings [inferred]), and the External Source as `MidiSideChain` (a routing, target `MidiIn/None` by default). No element for the Tapping Point was found apart from that routing.
