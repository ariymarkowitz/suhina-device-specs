# Beat Repeat (manual 29.5)

**Family:** delay and looping
**Note status:** dump checked

## Summary

A tempo-synced stutter effect. At moments chosen by Interval, Offset and Chance, it grabs a slice of
the incoming audio (the grid size) and repeats it for the length of Gate, with optional pitch
drop, decay, filtering and random changes of the slice size. The repeats can be mixed with the
input, replace it while they sound, or be the only output [manual].

## Signal flow

```text
in ──────────────────────────────────────────────────────────────┐
 │                                                               ▼
 └─► [capture buffer, length = Grid] ─► repeat player ─► [Pitch (resample)] ─► [Filter] ─► Decay ─► Volume ─► (mix mode) ─► out
          ▲ trigger from: Interval + Offset (+ Chance), or Repeat button      │
          └─ Grid chosen at trigger, varied by Variation ─────────────────────┘
mix mode: Mix = in + repeats;  Insert = repeats replace in while active;  Gate = repeats only
```

- Triggers come from the transport position: every Interval, shifted by Offset, with probability
  Chance [manual]. The Repeat button forces capture and repeating immediately, bypassing Interval,
  Offset, Chance and Gate, until released [manual].
- The filter and Volume apply to the repeats only; Volume does not change the dry signal
  [manual, source: 2, 3].
- The mix-mode stage decides what leaves the device [manual].

### Context menu and hidden options

None documented [manual]. Beat Repeat has no side-chain and no sync switch: it is always
tempo-synced [manual].

## Behaviour

- **Trigger timing.** The device derives a bar position from the transport. A cycle of length
  Interval starts at the beginning of the bar (or song); the capture starts Offset after the
  cycle start [manual, inferred]. With Chance < 100 % each trigger is accepted with that
  probability [manual]. If the transport is stopped, the position source is [measure] (a
  free-running clock is likely [inferred]).
- **Capture and repeat.** At the trigger, the incoming audio for Grid length is written into a buffer
  (the slice) and then played repeatedly, once every Grid, for the total Gate length [manual].
  Whether the first slice is heard once as it passes (the dry signal) then repeated, or whether
  the slice played back is the grab from before the trigger, is [measure]. Gate ≤ Grid gives no
  repeats [source: 2, 3].
- **Grid.** Chosen at each trigger, from Grid plus Variation. With the Variation 0 the Grid is
  fixed [manual]; the set of allowed values excludes triplets if No Triplets is on
  [manual]. The Variation range in grid steps is [measure].
- **Variation modes.** Trigger = one random grid per trigger. 1/4, 1/8, 1/16 = a fresh draw at
  these regular intervals within a trigger [manual]. Auto = after every repetition [manual].
- **Pitch.** Resampling playback: a lower pitch reads the slice more slowly, so the repeat takes
  longer than the Grid; the repetition does not hold the Grid length [manual, inferred]. The
  pitch law is probably `speed = 2^(semitones/12)` [inferred]. Whether the next repeat starts
  on the grid (overlapping or cut) or after the slice ends is [measure].
- **Pitch Decay.** Taper of the pitch curve across successive repeats [manual]; each repeat lower
  than the previous, by an amount that grows with the knob [manual]. Exact curve [measure]; a
  forum request for negative values hints that positive values lower the pitch more each time
  [source: 4, inferred].
- **Filter.** A band-pass on the repeats set by Freq and Width; the device manual says it
  combines a low-pass and a high-pass, i.e. the same linked-band structure as Filter Delay's X-Y
  controller [manual, inferred]. Slopes [measure].
- **Decay.** A gain multiplier applied to each repetition compared to the previous
  [manual]; curve [measure].
- **Mix modes.** As described above; Insert switches the dry input off exactly while
  repeats are active [manual]. Fade and crossfade lengths at the switching points are [measure].
- **Volume.** Only the repeats [manual].
- **Stereo.** Probably stereo-linked, with the same slice timing for both channels [inferred].
- **Latency.** None reported [inferred].

## Edge cases

- Gate ≤ Grid: nothing repeats [source: 2, 3]. Gate shorter than Offset spacing: irrelevant
  because the next trigger comes at the next Interval [inferred].
- Interval shorter than Gate: a new trigger arrives while repeating; whether it restarts or is
  ignored is [measure].
- Chance 0 %: only the Repeat button works [source: 5].
- Repeat button while Chance and Interval would trigger: Repeat takes precedence and the
  triggers are ignored [manual].
- Transport stopped: [measure]. Loop jump or tempo change during repeats: slice length is
  fixed in samples at the trigger, so repeats do not follow a tempo change until the next trigger
  [inferred; measure].
- Variation Auto with triplets allowed: the most irregular result [manual].
- Pitch very low: slices stretch to many times their length; a buffer of the longest allowed
  slice at the lowest pitch must exist [inferred].
- Repeat released mid-slice: the current repeat stops or finishes [measure].
- Mono input: output mono [inferred].

## Measurement plan

1. ~~**Value lists and ranges.**~~ Mostly answered by the dump of 12.4.6 (see Controls). Still open: the unit of Width.
2. **Trigger timing.** Click track and a tone on a 120 BPM project; set Interval 1 Bar, Offset
   8/16, Gate 4/16, Grid 1/16, Chance 100 %: render and read the start and length of each repeat
   in samples; repeat for other Interval and Offset values and with the transport stopped.
3. **Capture source.** Feed a ramp (sweep) signal so each slice is recognisable; check whether the
   repeated slice is the audio just before, at, or just after the trigger.
4. **Chance.** Run 100 bars at 25, 50 and 75 % and count triggers.
5. **Variation modes.** Run long renders with Variation 50 % in each mode; histogram of
   grid sizes, and when changes occur (at trigger, quarter, eighth, sixteenth, per repetition);
   confirm the effect of No Triplets.
6. **Pitch and Pitch Decay.** 1 kHz tone: measure each repeat's frequency for Pitch −12 with
   Pitch Decay 0, 33, 100 %; derive the decay curve.
7. **Decay.** Constant-level noise: level of each repeat for Decay 0, 33, 100 %.
8. **Filter.** White noise: response at several Freq and Width values.
9. **Mix modes.** Click-track input: check dry presence in each mode before, during and after
   Gate; measure crossfade times at the switch.
10. **Interactions.** Interval shorter than Gate; Repeat while Chance 0; tempo change during a
    repeat.

## Implementation notes

- **Building blocks:** a biquad band-pass with the bandwidth in octaves, parameter smoothing
  (gain and mix transitions), dB conversions.
- **Also needed:** a trigger scheduler driven by the transport's bar and beat position, a
  capture buffer with an interpolated (resampling) read, a note-value/grid table including
  triplets, a random source with repeatable seeds (a hash of the position works), the three-way
  mix logic.
- Output behaviour in Insert mode needs a gain ramp to avoid clicks; the real device's ramp
  is [measure].
- **Hard to match:** exact trigger semantics, Pitch Decay, Variation distribution.
- **.als element name:** `BeatRepeat` [als 12.4.6]. Parameter elements [als 12.4.6]: `On`, `Chance`
  (stored 1 = 100 %), `Interval` (stored 5 = position index), `Offset`, `Grid` (stored 7), `BlockTripplets`
  (sic), `GridChance` (probably the Variation amount), `GridChanceType` (probably Variation mode), `Gate`
  (stored 6), `DampVolume` (probably Decay), `DampPitch` (probably Pitch Decay), `BasePitch` (probably
  Pitch), `MixType`, `WetLevel` (probably Volume, stored 1 = linear gain, 0 dB), `FilterOn`, `MidFreq`
  (Hz, stored 1000), `BandWidth` (stored 4), `InstantRepeat` (probably the Repeat button). The pairing
  of the last seven names with panel controls is by name, not confirmed. Interval, Offset, Grid and Gate
  are stored as position indices (the same numbers as the API's loaded values).
