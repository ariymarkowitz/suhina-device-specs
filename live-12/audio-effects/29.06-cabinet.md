# Cabinet (manual 29.6)

**Family:** distortion
**Note status:** dump checked

## Summary

Cabinet emulates five classic guitar speaker cabinets, a virtual microphone in three positions and
two microphone types, developed with Softube [manual]. It is normally placed after Amp, but also
works alone as a filter and colour on drums, synths and other sources [manual]. It has no distortion
controls of its own; it behaves like a linear (or nearly linear) speaker-and-microphone filter,
which makes it well suited to convolution [inferred].

## Signal flow

```text
input ─► speaker cabinet (Speaker) ─► microphone (Microphone position, Dynamic | Condenser) ─► Dry/Wet ─► out
          [manual]                     [manual]                                                [manual]
 └────────────────────────────────────────────────────────────────────────► dry ──────────────┘
```

- Mono or Dual (stereo) processing is selected by the Output switch [manual].
- "Optimized mics and mic positioning": the response is built from speaker, position and mic type [manual].
- Whether the emulation is purely linear (an impulse response) or has speaker non-linearity is [measure].

## Behaviour

- **Speaker.** Each entry sets a speaker response: cone size and count give different resonance, bandwidth and low-frequency extent [inferred]. A large cabinet (4x12) is probably darker and fuller; a small one (1x12) brighter and thinner [inferred].
- **Microphone.** The position changes the frequency response (proximity effect, high-frequency roll-off off-axis) and adds room character for Far [manual]. The Far position includes "characteristics of the virtual room" [manual], so some short reverb or early reflection may be included [inferred].
- **Mic type.** Dynamic: a gritty, mid-forward response with high-frequency roll-off; Condenser: a more extended, flatter response [manual]. SOS and the manual both treat the virtual condenser as free from overload [manual].
- **Structure.** The most likely implementation is a fixed filter or a short convolution per Speaker × Position × Type combination (5 × 3 × 2 = 30 responses) [inferred]. The manual states "physical modelling", which could mean a parametric model of the speaker, cabinet and microphone instead [manual]. Both give a linear time-invariant sound, unless the speaker model has non-linearity [measure].
- **Mono vs Dual.** In Dual mode each channel has its own processing; in Mono the mono sum is processed [inferred]. For a stereo source, Dual keeps the stereo image [source: 3].
- **Multiple mics.** Several Cabinets in an Audio Effect Rack with different microphone settings, mixed in the rack's mixer, give a multi-mic sound [manual].
- **Dry/Wet.** Linear [inferred]; dry delay compensation if the model adds latency is [measure].

## Edge cases

- **Impulse input:** the output is the cabinet's impulse response (length [measure], possibly hundreds of ms for Far).
- **Silence tail:** if the model is IIR or convolution there is a ring-out [inferred].
- **Mono source in Dual:** identical outputs, unless the Dual mode adds a stereo difference (for example, a decorrelated Far microphone) [measure].
- **Switching Speaker or Microphone while playing:** crossfade or hard switch [measure].
- **Sample rate:** if built from stored impulse responses, they are resampled [inferred].
- **Latency:** [measure] (linear-phase would add latency, minimum-phase would not).
- **Level:** loudness differences between the entries are likely and not normalised [measure].

## Measurement plan

1. **Responses.** Impulse and logarithmic sine sweep at -20 dBFS through Cabinet with Dry/Wet 100 %, for every Speaker (5) × Microphone (3) × type (2) = 30 combinations, in Mono: record the impulse response (length, phase, latency) and magnitude response (using deconvolution). Check for a short reverb part in Far.
2. **Linearity.** The same sweep at -40, -20, -6, 0 dBFS: compare the responses; any change means speaker non-linearity or compression.
3. **Mono vs Dual.** Stereo-different input (left sweep, right silent): compare left/right outputs in Mono and Dual; check if the Dual mode decorrelates a mono source (mono sweep in both channels).
4. ~~**Entries and defaults.**~~ Answered by the dump of 12.4.6 (see Controls).
5. **Dry/Wet.** 50 % compared with 0 % and 100 %, impulse for dry-path delay.
6. **Level.** Pink noise through each entry: loudness differences.

## Implementation notes

- **Building blocks:** biquad peaks, shelves, low-pass and high-pass can approximate a response with a handful of sections; parameter smoothing for Dry/Wet.
- **Also needed:** a convolution engine (FFT partitioned convolution, real-time safe, no allocation in the callback) and 30 original impulse responses, or a filter bank fitted to the measured magnitude responses. Impulse responses measured from Live's Cabinet cannot be shipped (clean-room: the data is derived from Ableton and Softube's models); the device's responses must be authored or measured from own sources, with Live's response only as a target for a fitted parametric model.
- **Hard to match:** the character of the Far position and the Dual stereo behaviour.
- **Pair:** Amp (29.1). The two should share the Mono / Dual convention.
- **`.als` element:** `Cabinet` [als 12.4.6]. Parameter elements [als 12.4.6]: `On`, `CabinetType` (0 to 4, stored 0 = 1x12),
  `MicrophoneTypeSwitch` (boolean, stored false; the API's step 0 is Condenser, so false is probably
  Condenser, not confirmed), `MicrophonePosition` (0 to 2), `DualMono` (boolean), `DryWet` (stored 1 = 100 %).
