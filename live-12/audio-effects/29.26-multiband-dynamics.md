# Multiband Dynamics (manual 29.26)

**Family:** dynamics
**Note status:** dump checked

## Summary

Splits the signal into up to three bands and gives each band two independent level-dependent gain stages: one above an "Above" threshold (downward compression, or upward expansion) and one below a "Below" threshold (upward compression, or downward expansion). A single instance can therefore do up to six kinds of dynamics processing at once [manual]. It was designed as a mastering tool; with ratios at 1 it works as a plain three-band crossover. Well-known uses: multiband compression, de-essing, "uncompression" (upward expansion) and presets such as OTT-style squashing [manual] [source: 2].

## Signal flow

Shared parts: [common.md](common.md) (side-chain; note that this device's side-chain has no EQ block).

```text
input ─► crossover split: Low | Mid | High (High and Low buttons switch bands on) [manual]
          Low band  ─► Input ─► [Below stage + Above stage] ─► Output ─┐
          Mid band  ─► Input ─► [Below stage + Above stage] ─► Output ─┼─► sum ─► global Output ─► device output
          High band ─► Input ─► [Below stage + Above stage] ─► Output ─┘
Detector source: own input, or external side-chain × Gain blended by the side-chain Dry/Wet [manual]
Each stage: level detector (Peak or RMS, shared switch) ─► static curve (threshold, ratio, Soft Knee)
            ─► attack / release (scaled by Time) ─► gain; ratio exponent scaled by Amount [manual]
```

- With both outer bands off, only the Mid controls act; the device is single-band [manual].
- The detector reads the band signal after Input gain (the input meters show the level before processing, the output bars after) [manual]. Where exactly the detector taps the band relative to Input is [measure].
- A deactivated band keeps its content out of the neighbouring band's processing: the split still happens, only that band's dynamics and gain controls are bypassed [manual] [source: 2].
- Dry/Wet in the side-chain section blends side-chain and own input as the detector's source, not the output [manual].

## Behaviour

**Crossovers.** Two crossover frequencies split the signal into three bands. The manual's example: low band 0 Hz to 500 Hz, mid 500 Hz to 2 kHz, high above 2 kHz [manual]. Filter slope and type are not documented. Forum users report that using the device as a splitter (ratios 1) colours the sound and shows boosts or notches near the crossovers, so the sum is not perfectly flat [source: 5] [measure]. The filters could be Linkwitz-Riley 24 dB/oct, minimum-phase or Butterworth; the reports do not settle which [inferred] [measure]. A deactivated band stays split off from its neighbours [source: 2].

**Static curve per band.** Two thresholds per band. Below the Below threshold the signal is processed by the Below stage, above the Above threshold by the Above stage, and between the thresholds the signal is unchanged (ratio 1) [manual] [inferred]. Above ratio R_a: output rises 1/R_a dB per dB above the threshold, so R_a > 1 is downward compression and R_a < 1 upward expansion. Below ratio R_b: output falls more than 1 dB per dB below the Below threshold if R_b < 1 (downward expansion) or less than 1 dB if R_b > 1 (upward compression) [manual] [inferred]. The ratio display "1:x" with x the compression ratio: 1:2.00 halves the dB distance, 1:0.50 doubles it. Typing 0.5 gives 1:2.00 and 2 gives 1:0.50 [source: 2], so the number typed is a slope and the display is its reciprocal [inferred].

**Amount.** Scales the ratios toward 1: at 0 % every ratio is effectively 1 [manual]. Probable form: the gain change from the static curve is multiplied by Amount, or the slope is moved toward 1 by Amount [inferred] [measure]. Whether Amount goes above 100 % is [measure].

**Time.** A single factor on all attack and release times [manual]. At 100 % it leaves the times unchanged [inferred]; range [measure].

**Envelope.** For the Above stage, Attack applies when the level crosses over the threshold, and Release when it falls back; for the Below stage Attack applies when the level crosses under the threshold, and Release when it rises back [manual]. Attack and release are probably time constants of a one-pole smoother on the gain in dB [inferred] [measure].

**Soft Knee.** Rounds the transition at both thresholds, width [measure]. A quadratic knee is likely [inferred].

**RMS / Peak.** One switch for all bands [manual]. Peak: the detector follows peaks; RMS: a short running mean of squares, window [measure] [inferred].

**Input and Output knobs.** Input is applied before detection and processing, band Output after; the global Output after the sum [manual]. A band's soloing mutes other bands (their processing continues so that the meters work, [inferred]) [manual].

**Display.** Bars show per-band levels, the "input" bars before the dynamics, the "output" bars after. Without processing, the input bars are aligned with the output bars' tops [manual].

**Side-chain.** An external signal, scaled by Gain, blended with the own input by Dry/Wet, drives the detectors of all bands; it is not heard [manual]. Whether the detector for each band sees the band-split side-chain signal or the full-range one is [measure] (the more usual design is that the same crossover splits the key).

**Latency.** The manual and the help centre mention none for Multiband Dynamics; whether the crossovers add latency is [measure].

## Edge cases

- Both High and Low off: only Mid acts, full range [manual].
- Crossover frequencies crossing each other (Low frequency above High frequency): [measure] (probably clamped so Low ≤ High) [inferred].
- Ratio 1 in all stages with Amount 100 %: crossover only; null-test result [source: 5] [measure].
- Amount 0 %: all ratios 1, but Input and Output gains and soloing still act [manual] [inferred].
- Below threshold at its minimum (a tutorial uses −80 dB): the Below stage never acts [source: 4] [inferred].
- Above threshold below the Below threshold: [measure].
- Very short attack with low band: bass distortion, as for any compressor [inferred].
- Switching band activators or High/Low while playing: clicks or a crossfade [measure].
- Silence in, denormals, sample rates: [measure].

## Measurement plan

1. ~~**Ranges, defaults and lists.**~~ Answered by the dump and the saved set for every parameter [dump 12.4.6] [als 12.4.6]. Still to read: what the High and Low buttons and the T/B/A buttons are (the dump has no parameters for them) and their defaults.
2. **Crossover response.** Impulse and swept sine through each band alone (solo each band, one crossover at a time, ratios 1, Input and Output 0): measure magnitude and phase for each band and for the sum with all three on. Gives filter type (LR, Butterworth), order or slope in dB/octave, band overlap and sum flatness at several crossover settings (100 Hz, 1 kHz, 10 kHz). Also test the near-Nyquist behaviour at 44.1 and 96 kHz.
3. **Latency.** Impulse through the whole device with all bands on and off; read the delay and compare with the title-bar latency tooltip.
4. **Static curves.** Per band, a sine at the band's centre in 1 dB steps from −80 to 0 dBFS; Attack and Release at their minimum; test the Above stage (Above ratios 1:2, 1:4, 1:0.5; Below ratio 1), the Below stage (reverse), Soft Knee off and on; read output versus input. Gives the slope per ratio, the interaction of the stages and the knee shape and width.
5. **Ratio field mapping.** The display range and the API-value-to-display map are answered [dump 12.4.6]. Still to do: type values 0.25, 0.5, 1, 2, 4, 10 into each ratio field and read the measured slope, to confirm that the displayed `1 : x` is really the reciprocal of the slope.
6. **Amount and Time.** Static curves with Amount 0, 25, 50, 100 % (and the maximum if it exceeds 100 %) at a fixed ratio 1:4: determine how the effective slope or gain change scales. Tone-step tests (below) with Time at its minimum, 50, 100 % and maximum: read how the attack and release times scale.
7. **Envelope times.** Tone steps across the Above threshold and across the Below threshold (up and down) with attack and release set to 10, 100, 1000 ms; fit exponentials; report 63 % and 10 %–90 % times; check that Above and Below use the attack and release as the manual says.
8. **RMS vs Peak.** Bursts of 1–300 ms at 6 dB over the Above threshold with minimum attack; compare the gain change in Peak and RMS; fit the RMS window.
9. **Detector tap.** With Input at +12 dB or −12 dB, check whether the thresholds are relative to the level before or after Input gain.
10. **Solo and deactivation.** Solo each band and read the output of the others; deactivate a band while its neighbours compress, read the neighbour's level to confirm the split remains; null test with all four ratio stages 1.
11. **Side-chain.** An external tone with the own signal silent and the reverse; Gain sweep; Dry/Wet 0, 50, 100 %; check per-band behaviour of the key (a low-frequency key and a high-frequency key with a broadband input signal).
12. **Dry/Wet of the side-chain and Listen.** Listen output spectrum: does it show the full-range key or the band-split key?
13. **Crossover edge cases.** Move the Low frequency above the High frequency and read the values.
14. **Meters.** Compare the bar heights with the measured levels (RMS vs peak weighting) and the scale's range.

## Implementation notes

- **Crossover:** Linkwitz-Riley filters (24 or 48 dB/oct, a low and a high split with an all-pass for phase alignment) are the first guess; three bands need two splitters plus all-pass compensation on the outer branch, whose phase response must match the one the measurements give. Biquads, one-pole envelopes, parameter smoothing and dB conversions cover the rest.
- **Also needed:** a per-band two-sided gain computer (above and below thresholds), an RMS detector, a level-dependent display model, Amount and Time scaling, band solo handling, side-chain plumbing ([common.md](common.md) › Side-chain section).
- The Above stage is a standard compressor gain computer (threshold, ratio, quadratic soft knee, dB-domain smoothing), as in Compressor (29.9); the Below stage is the same function mirrored.
- The display can follow the manual's interactions (bars, drag edges and middles, modifier keys), since they are plain UI behaviour.
- `.als` import: the element is `MultibandDynamics` [als 12.4.6]. Parameter elements in the set saved from Live 12.4.6 [als 12.4.6], each holding a `Manual` value: `On`, `SplitLowMid` and `SplitMidHigh` (Hz), `SoftKnee` (bool), `EnvelopeIsPeak` (bool, false = RMS), `OutputGain` (dB), `GlobalAmount` (fraction), `GlobalTime` (factor, 1 = 100 %), and per band (suffix `Low`, `Mid` or `High`): `GainLow`/`GainMid`/`GainHigh` (band output gain, dB), `InputGainLow`/`Mid`/`High` (dB), `ActiveLow`/`Mid`/`High` (bool), `AboveThresholdLow`… and `BelowThresholdLow`… (dB), `AboveRatioLow`… and `BelowRatioLow`… (the API values, 0 for 1 : 1.00; see the ratio rows), `AttackLow`… and `ReleaseLow`… (ms), and `SideChain/OnOff` (bool), `SideChain/RoutedInput/Volume` (linear gain, 1 = 0 dB), `SideChain/DryWet` (fraction). Times, thresholds and gains are therefore stored in physical units, not as the log-domain API values.
