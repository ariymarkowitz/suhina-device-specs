# Spectrum (manual 29.38)

**Family:** analysis and utility
**Note status:** dump checked, partly measured (remaining run, [Measured](#measured))

## Summary

A real-time spectrum analyser that sits in a device chain and does not change the audio. It shows
level in dB against frequency (or pitch), with settings for the size of the analysis block, how
often it measures, how many blocks it averages, which channel it reads, a line or bin graph, a
held maximum, the frequency axis scale and the visible level range [manual].

## Signal flow

Shared parts: [common.md](common.md) (title bar only).

```text
input ─────────────────────────────────────────────────────────────► output (unchanged) [manual]
  └─► channel select (L, R, L+R) ─► block of N samples ─► window + FFT ─► magnitude in dB
        ─► average over Avg blocks ─► [max hold] ─► display (Scale X, Range)
        every Refresh interval [manual]
```

- The device never alters the audio [manual]. Whether it reports latency or adds a delay is [measure];
  an analyser should be transparent, so none [inferred].
- Window function, FFT scaling, dB reference and the way two channels are combined for L+R
  are [measure].

## Behaviour

- **Analysis.** A fast Fourier transform of a block of Block samples (for a block size N, the
  frequency resolution is the sample rate divided by N), with a window to limit leakage, magnitudes in
  dB [inferred]. Block size and Refresh are separate: Refresh sets how often a block is analysed,
  so blocks may overlap [inferred]. A forum user measured the default Refresh at about 60 ms and
  noted that a block of 16384 samples is about 300 ms at 44.1 kHz [source: 2].
- **Averaging.** Avg averages that many consecutive spectra for each display update [manual]; whether
  the average is in the power or dB domain, and whether it is a running or block average, is
  [measure].
- **Max.** Tracks the highest value of each bin since it was reset (click) or since playback restarted
  [manual].
- **Channel.** Left, right or both; for both, probably the average or power-sum of the two
  channels' spectra, or the spectrum of the mid [measure].
- **Scale X.** Linear spacing; logarithmic (Hz legend); semitone (note-name legend) [manual].
- **Range.** Fixed window or automatic scaling [manual].
- **Consistency with EQ Eight.** The EQ Eight analyser and Spectrum once differed by about 10 dB on
  the vertical axis; Ableton fixed it in a Live 11 beta [source: 3]. So the two should agree on level.
- **Latency and bypass.** The device passes audio through bit-exact [inferred].

## Edge cases

- **Silence:** the display falls to its floor [inferred]; the floor value is [measure].
- **Peaks held:** until the song restarts [manual] (when Max is on [measure]).
- **Auto range:** sliders disabled [manual].
- **Mono input:** left, right and both agree [inferred].
- **High block with low refresh:** CPU use; no effect on audio [inferred].
- **Sample rate change:** frequency axis rescales [inferred].

## Measured

[measured 12.4.6] Behaviour run at 44.1 kHz in Live 12.4.6 (`measurements/29.38-spectrum/`: `spectrum-transparency`, in the remaining set): the device switched on against the bypass render, through every segment of the probe (impulse, sweep, staircase, bursts, steady tone, noise, left only, right only, silence). The device is not in the top100 set; this is its first measurement. These are observations, not a model.

- **The Spectrum leaves the audio exactly as it is**: the render with the device on is bit-identical to the bypass render, sample for sample, in all segments, and the impulse comes out at 0 ms with a gain of 1.000: no gain, no latency, no noise, no DC (silence stays at -240 dB) [measured 12.4.6]. The display itself, its scales and its averaging are not audio and were not measured.

## Measurement plan

1. **Settings.** The dump lists no panel parameters beyond Device On [dump 12.4.6]. The saved set stores the settings as plain values, which give the defaults [als 12.4.6] (see Controls). Still to read from the display: the lists and ranges of Block, Refresh, Avg and the Range sliders, the Block default (stored as index 2), and which window function `Window` = 3 names, if the panel shows it at all.
2. **Level scale.** A 1 kHz sine at -6, -20, -40 dBFS: the dB read at the peak for each Block size; a
   white noise at -20 dBFS RMS: the level of the flat spectrum against Block (bin normalisation).
3. **Window.** A sine between two bins: the peak width and side-lobe level (the window type).
4. **Refresh and averaging.** Tone bursts: the time between display updates against Refresh, the
   smoothing against Avg (time to settle); average in dB or power (two tones of different level).
5. **Channels.** A signal only in the left channel: readings for left, right, both.
6. **Max and Graph.** Max reset behaviour; the line against bins (interpolation).
7. **Axes.** The labels and position of 100 Hz, 1 kHz, 10 kHz for linear, log and semitone; the note
   names against pitch.
8. **Latency/transparency.** Null test against the dry.
   Done: the render with the device on is bit-identical to the bypass render (Measured).

## Implementation notes

- **Building blocks:** an FFT library (for example `rustfft` or `realfft`, MIT/Apache-2.0);
  windowing, averaging and display scaling.
- **Needs:** an analysis tap off the audio thread's critical path: the device copies blocks into
  a lock-free queue for a non-real-time analyser, since the FFT must not run in the audio
  callback (real-time safety). The UI draws it.
- **`.als` element:** `SpectrumAnalyzer` [dump 12.4.6] (the summary header; the display name is Spectrum). Parameter elements [als 12.4.6]: only `On` (true). The settings are not parameters but plain values on the device element [als 12.4.6]: `Length` (Block, an index, 2), `ChannelMode` (2 = both), `MinRefreshTime` (ms, 60), `NumAverages` (1), `ShowBins` (false = line), `ShowMax` (true), `ScaleXMode` (1 = Logarithmic), `AutoScaleY` (false = Range), `ScaleYBegin` (0) and `ScaleYRange` (80) for the dB window, `AnalyzeOn` (true) and `Window` (3, an analysis window function with no control named in the manual). The meanings of the numbers are [inferred]. EQ Eight stores the same set of values under its `SpectrumAnalyzer` element.
