# Note Length (manual 30.4)

**Family:** note transformation
**Note status:** dump checked, partly measured (MIDI recordings, [Measured](#measured))

## Summary

Replaces the length of every incoming note with a length set on the device, either in
milliseconds or in beats of the song tempo, scaled by a Gate percentage. It can instead trigger
its note when a key is *released* rather than pressed, in which case the new note begins at the
moment the incoming note ended, with a velocity made from the press and release velocities, a
decay over the time the key was held, and optionally a length that depends on pitch. A Latch
mode (new in Live 12.0) holds the notes on until the next gesture. Typical uses: turning held
notes into fixed-length notes, staccato or legato from any input, MIDI delays built from two
instances, and release-triggered notes [manual; source: 4].

History: the device exists since early Live versions (a 2006-era forum thread already describes
the Note On / Note Off triggers and absolute lengths [source: 5]). Live 12.0 added Latch, swapped
the Gate and Length knobs, split the Time mode toggle into two buttons placed below Length, renamed
"Release Vel.2" to Rel Vel (the manual calls it Release Velocity) and "Decay Time" to Decay
[source: 2]. Live 11.1 fixed a wrong velocity in release mode when a note was released after
being recorded in a loop [source: 3]. 12.1 fixed missing MPE data when the device sits inside or
after a MIDI Effect Rack, and superfluous MPE events [source: 2].

## MIDI flow

Shared parts (title bar, note-off and MPE handling, racks, latency, sync and transport):
[common.md](common.md). This device has no Use Current Scale toggle [manual].

```text
Trigger Source = Note On
   note-on (p, v) at t ─► note-on (p, v') at t ──────────────► note-off at t + Length × Gate
   incoming note-off ────► ignored for the output [measured 12.4.6]

Trigger Source = Note Off
   note-on (p, v_on) at t_on ─► nothing sent; the device remembers it and runs the Decay [manual]
   note-off (p, v_off) at t_off ─► note-on (p, v_out) at t_off ─► note-off at t_off + Length' × Gate
        v_out from Release Velocity, v_on and Decay [manual]; Length' = Length scaled by Key Scale [manual]

Latch on:  Gate and Length are replaced by the keys and sustain pedal (below) [manual]
```

- Stages applied to notes only; all other messages (CC, pitch bend, aftertouch) pass through
  [inferred]. Output pitch is the input pitch; the device never changes it [inferred].
- In Note On mode the output note-on is simultaneous with the input one (no delay) [measured
  12.4.6]; in Note Off mode the input note-on produces no output at all and the output note starts
  at the input note's end [manual; measured 12.4.6].
- Velocity of the output in Note On mode: the incoming velocity, unchanged; Release Velocity,
  Decay and Key Scale have no effect there (recorded at their extremes, with note-on velocities 1,
  64 and 127 and release velocities 1, 64 and 127) [measured 12.4.6].
- Where the clock enters: lengths in Sync mode are beats of the song tempo (the recordings are at
  120 BPM only); the end time of a note is a scheduled event on the transport/audio-time clock
  [inferred; measure].

## Behaviour

**Note On mode.** Each incoming note-on starts an output note of the same pitch at the same
time, with the same velocity. Its length is `Length × Gate / 100` whatever the input note's
length: inputs of 1 beat, 1/16 beat and 2 beats all gave the same output length, and the incoming
note-off is consumed [measured 12.4.6]. So a note held longer than the output length is cut, and
a short tap becomes a longer note. Time-mode lengths in beats at 120 BPM: 10 ms gave 0.02, 500 ms gave 1,
1 s gave 2 and 5 s gave 10; Gate 25, 50 and 200 % of 500 ms gave 0.25, 0.5 and 2 beats; the
minimum, 10 ms, is not a zero-length note [measured 12.4.6]. In Sync mode Length is a fraction of
the whole note (4 beats) converted to time by the song tempo [measured 12.4.6 at 120 BPM]; whether
a tempo change during the note moves the end is [measure]. The same pitch retriggered while the
previous output still sounds: the earlier note ends at the new note-on (a note every half beat
with a one-beat length came out as notes of half a beat, the last one a full beat), in both
trigger modes [measured 12.4.6].

**Note Off mode.** The device holds on to each incoming note-on until the note-off. At the
note-off the note starts, at that instant, with the same pitch (inputs of 1 beat, 1/16 beat and
2 beats gave outputs at beats 1, 12.0625 and 26) [measured 12.4.6]; its length is then Gate ×
Length as in Note On mode (200 ms gave 0.4 beats) [measured 12.4.6]. A forum post says the
repeated note begins at once on the note-off with no way to put a delay in front of it [source: 5,
partly]. Combining two instances (one on Note Off, one on Note On) makes a MIDI delay [source: 5].
For a note from a MIDI clip the incoming note-off is the clip note's end, so a clip note's length
sets the delay; the clip note's release velocity is the `v_off` below (64 by default) [measured
12.4.6].

**Output velocity in Note Off mode.** With the note-on velocity `v_on`, the release velocity
`v_off`, the hold time `d = t_off − t_on` in seconds, Decay `D` and Release Velocity `R`
(percent) [measured 12.4.6]:

`v_out = max(1, (1 − R/100) × v_dec + R/100 × v_off)`, with `v_dec = v_on × 126^(−d / D)`.

- With R = 0 the output is the decayed note-on velocity; the release velocity does not matter.
  With R = 100 it is the release velocity. R = 50 gave 64 for v_on 1 with v_off 127 and 32.5 for
  v_on 64 with v_off 1 (a plain average).
- Decay: the velocity is multiplied by 126 to the power of minus the share of the Decay time that
  was held, so the level falls 42 dB over Decay (to 1/126). Held 0.2 s with Decay 2 s, 1 s and
  0.5 s gave 61.7, 38.0 and 14.5 from velocity 100; held 0.5 s with Decay 2 s and 1 s gave 29.9 and
  8.9; held for the whole Decay the result is 0.8 and is floored at 1. The Decay time is counted from
  the note-on of the same note. At its default, 60 s, a tap does not decay.
- Decay is applied to the note-on velocity before the balance: R = 50, Decay 500 ms and a 200 ms
  hold of velocity 100 with release velocity 64 gave 39.2 (the mean of 14.5 and 64), and held 0.5 s
  or more it gave 32.4 (the mean of the undecayed floor 0.8 and 64).
- The 11.1 fix says the velocity was wrong when a note was released after being recorded in a
  loop [source: 3]: the device times Decay from the note-on of the *same* note, including notes
  that began before a loop jump [inferred; not recorded].

**Key Scale.** The manual says the output length depends on `pitch − C3`, longer for low notes
with positive values [manual]. The one recording that could show an effect points to the Decay
time instead: at Key Scale −1, Decay 500 ms, a hold of 500 ms and pitch 24 the output velocity was
2.66 (a Decay time 4/3 as long), while pitch 36 to 96 stayed at the floor of 1, and at −0.5, +0.5 and
+1 every pitch was at the floor, so that run does not fix the pivot or the law; the output
lengths were 1 beat for every pitch and every Key Scale (Length 500 ms) [measured 12.4.6]. A
better run (long Decay, short hold) is [measure]. The control has no effect in Note On mode
[measured 12.4.6], as the manual says.

**Latch.** Both modes replace Gate and Length with the player's own gestures [manual]. The
recording of a chord (C, E, G pressed together for 4 beats), then a note at beat 8 (held 2 beats)
with a second one pressed at beat 9 while it is held (2 beats), then a separate note at beat 14
(1 beat) [measured 12.4.6]:
- *Note On + Latch.* The chord's notes sound from beat 0 and end at beat 8, when the next gesture
  starts (the first note-on with no key held); the two notes of the second gesture start at 8 and 9 and
  end together at 14, when the third gesture starts; the last note keeps sounding to the end of the
  recording. Length and Gate are ignored (Length was 500 ms). A note pressed while another is
  held (beat 9) joins the current gesture and does not end the earlier notes.
- *Note Off + Latch.* The chord's notes all start at beat 4, when the last key is released, and
  end at beat 10, the first note-off of the next gesture (the first note, released at 10, starts
  at 10 and takes the chord with it); the second note of that gesture starts at its own note-off,
  beat 11, and the earlier ones stay; the third gesture's note starts at its note-off, beat 15, and
  ends the second gesture's two notes there; it sounds to the end of the recording.
- A gesture is a note-on with no key held; a trigger of a later gesture ends all notes of the
  earlier ones at its own instant.
- The sustain pedal (CC 64) in Latch mode [manual]; outside Latch mode it is ignored [source: 7,
  partly]: not recorded [measure].

**Held notes.** In Note On mode a held key does not extend the output past Length × Gate; in Note
Off mode a note-on with no note-off yet produces nothing. The device switched off while a long
output note sounds ends it at once: with Length 5 s (10 beats) and the device off at beat 2 and
on at beat 4, both output notes ended at beat 2 and did not come back. In Note Off mode with an
input held from 0 to 6, the device off from 2 to 4 and on again, the note-off at 6 still triggered
its output (a 10-beat note at beat 6), and the held note was not passed through while the device
was off. The one that ended at 1 triggered its output, which was cut at 2 by the switch-off
[measured 12.4.6]. Switching Trigger Source with notes held: [measure]; see
[common.md](common.md) › Switching a device off while notes sound.

**MPE.** Per-note expression goes with the note in Note On mode [inferred]; in Note Off mode the
expression data that arrived while the key was down has nothing to apply to [inferred; measure]. See
[common.md](common.md).

**Latency.** No latency is reported; the delay in Note Off mode is a musical delay, not host
latency [inferred].

## Edge cases

[measured 12.4.6] where tagged, the rest [measure].

- **Note longer than the output** (Note On mode): the output ends first; the later input
  note-off is consumed [measured 12.4.6].
- **Output longer than the gap to the next note of the same pitch** (a repeated note): the
  earlier note ends at the new note-on [measured 12.4.6].
- **Zero-length and very long output**: Synced Length step 0 gives no note; Time Length 10 ms
  gives 10 ms [measured 12.4.6]. Gate 1 % gave 2.5 ms at Length 500 ms, not 5 [measured 12.4.6].
  Length at its maximum with Gate 200 % (the forum's 120 s trick is a use as an infinite latch
  [source: 6, partly]): not run.
- **Transport stop / loop jump with output notes sounding:** pending note-offs fire at once or
  at their time? Note Off mode with the clip note ending at the loop end: does the trigger occur?
  Notes held across the loop end in a clip. Not recorded (the set has no looped clips); a latched
  note at the end of the take lasted to the end of the recording.
- **Tempo change** during a Sync-mode note (end time in beats): not recorded.
- **Velocity 1 and 127** in Note Off mode with Release Velocity 100 %: the output equals the
  release velocity (1, 64, 127); the result of 0 does not occur (floor 1) [measured 12.4.6].
- **Pitch extremes** with Key Scale at its extremes (MIDI 0 and 127): not run.
- **Sustain pedal** held: not recorded.
- **Switching Trigger Source or Latch while notes are held or sounding:** not recorded.
- **Gate or Length automated while a note sounds:** not recorded.
- **Device in a Rack / after another effect that changes pitch:** the pairing of note-offs
  (common.md).

## Measured

Recorded from Live 12.4.6 (`devices/30.04-note-length/results/*.json`; runs `note-length-time`,
`-sync`, `-trigger`, `-velocity`, `-keyscale`, `-latch`, `-repeat`, `-held`; 120 BPM), see
Behaviour for the numbers [measured 12.4.6]:

- Trigger Source Off is Note On and On is Note Off. Output pitch and, in Note On mode, velocity are
  the input's; start and end are exact (to the recording's resolution).
- Length is in time or beat units and exact; Gate is a plain factor (but 1 % is 2.5 ms, not 5).
- Note Off velocity: `max(1, (1 − R) × v_on × 126^(−d/D) + R × v_off)`.
- Latch ends the earlier gesture's notes when a later gesture's first note triggers.
- A same-pitch retrigger cuts the earlier note; switching the device off ends sounding notes at once.

Not measured: Key Scale's law and pivot (one weak data point), tempo changes and 90 BPM, CC 64,
loop and transport stop, MPE.

## Implementation notes

- A per-block event list in/out plus a scheduler of timestamped output events (note-offs in
  Note On mode; whole notes in Note Off mode). Sample-accurate in seconds; Sync lengths converted
  from beats using the tempo map so a tempo change moves the end.
- Held-note table keyed by (channel, pitch), storing `t_on`, `v_on` and the output note for each
  input note, so the input note-off finds its note (Note Off mode) or is consumed (Note On mode).
  Keep the output note id so the scheduled note-off ends the right instance.
- Latch needs a count of held keys and the CC 64 state, plus a set of latched output notes.
- Velocity maths in Note Off mode: `v_dec = v_on × 126^(−d/D)`, balance with the release velocity
  after it, floor at 1, no rounding needed (recorded velocities are fractional, as for Velocity).
- Hard to match: Key Scale's law, Gate 1 %'s odd value, the end-of-recording behaviour of
  latched notes.
- **`.als` import.** The device element is `MidiNoteLength` [als 12.4.6]. Parameter elements,
  in stored order [als 12.4.6]: `On`, `Mode` (Trigger Source, bool, false in a fresh device),
  `Latch` (bool), `SyncState` (Sync On, bool), `SyncedLength` (index 0 – 9), `TimeLength`
  (**stored in ms**, 10 – 60000; the API's 0 – 1 is the log taper above), `Gate` (percent,
  1 – 200), `Balance` (Release Velocity, percent, 0 – 100), `DecayTime` (**stored in ms**,
  10 – 60000), `DecayKeyScale` (−1 – 1). The stored ranges are the elements'
  `MidiControllerRange`. No other state is stored.
