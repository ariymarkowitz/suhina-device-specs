# Note Length (manual 30.4)

**Family:** note transformation
**Note status:** dump checked

## Summary

Replaces the length of every incoming note with a length set on the device, either in
milliseconds or in beats of the song tempo, scaled by a Gate percentage. It can instead trigger
its note when a key is *released* rather than pressed, in which case the new note begins at the
moment the incoming note ended, with a velocity made from the press and release velocities, a
decay over the time the key was held, and optionally a length that depends on pitch. A Latch
mode (new in Live 12.0) holds the notes on until the next gesture. Typical uses: turning held
notes into fixed-length notes, staccato or legato from any input, MIDI delays built from two
instances, and release-triggered notes [manual; source: 4].

History: the device exists since early Live versions (a 2006-era forum thread already describes
the Note On / Note Off triggers and absolute lengths [source: 5]). Live 12.0 added Latch, swapped
the Gate and Length knobs, split the Time mode toggle into two buttons placed below Length, renamed
"Release Vel.2" to Rel Vel (the manual calls it Release Velocity) and "Decay Time" to Decay
[source: 2]. Live 11.1 fixed a wrong velocity in release mode when a note was released after
being recorded in a loop [source: 3]. 12.1 fixed missing MPE data when the device sits inside or
after a MIDI Effect Rack, and superfluous MPE events [source: 2].

## MIDI flow

Shared parts (title bar, note-off and MPE handling, racks, latency, sync and transport):
[common.md](common.md). This device has no Use Current Scale toggle [manual].

```text
Trigger Source = Note On
   note-on (p, v) at t ─► note-on (p, v') at t ──────────────► note-off at t + Length × Gate
   incoming note-off ────► ignored for the output [inferred; source: 5: length is absolute]

Trigger Source = Note Off
   note-on (p, v_on) at t_on ─► nothing sent; the device remembers it and runs the Decay [manual]
   note-off (p, v_off) at t_off ─► note-on (p, v_out) at t_off ─► note-off at t_off + Length' × Gate
        v_out from Release Velocity, v_on and Decay [manual]; Length' = Length scaled by Key Scale [manual]

Latch on:  Gate and Length are replaced by the keys and sustain pedal (below) [manual]
```

- Stages applied to notes only; all other messages (CC, pitch bend, aftertouch) pass through
  [inferred]. Output pitch is the input pitch; the device never changes it [inferred].
- In Note On mode the output note-on is simultaneous with the input one (no delay) [inferred];
  in Note Off mode the input note-on produces no output at all [manual: in that mode the note is
  started by the note-off].
- Velocity of the output in Note On mode: the incoming velocity, unchanged [inferred; measure].
- Where the clock enters: lengths in Sync mode are beats of the song tempo; the end time of a
  note is a scheduled event on the transport/audio-time clock [inferred; measure].

## Behaviour

**Note On mode.** Each incoming note-on starts an output note of the same pitch at the same
time. Its end time is `t_on + Length × Gate / 100` regardless of when the key is released
[manual: the output length comes from Gate and Length; source: 6: the length does not
depend on how long the key is held]. So a note held longer than the output length is cut, and a short tap becomes a longer
note. The incoming note-off is consumed: the output note-off is generated by the device, the
input one must not also be passed [inferred]. A gate above 100 % lengthens the note past Length,
below 100 % shortens it [manual]. In Sync mode Length is a fraction of the whole note (4 beats)
converted to time by the song tempo [inferred]; whether a tempo change during the note moves the
end (it should if the end is kept in beats) or not is [measure]. The shortest output (Gate and
Length at their minimum, for example 0 ms) and whether a note can have zero length are [measure].
The same pitch retriggered while the previous output still sounds: the earlier note must end
(note-off) before or at the new note-on, or it retriggers; [measure].

**Note Off mode.** The device holds on to each incoming note-on until the note-off. At the
note-off the note starts: an incoming note is delayed by its own length, the new note
starting at the moment the old one would have ended [manual]. Once started, its length
follows Gate × Length, exactly as in Note On mode [manual: after the initial delay, Gate and
Length set the length]. A forum post says the repeated
note begins at once on the note-off with no way to put a delay in front of it [source: 5, partly].
Combining two instances (one on Note Off, one on Note On) makes a MIDI delay [source: 5].
For a note from a MIDI clip the incoming note-off is the clip note's end, so a clip note's length
sets the delay; a clip's notes carry a release velocity that defaults to 64 [inferred; measure].

**Output velocity in Note Off mode.** Three inputs: the note-on velocity `v_on`, the note-off
(release) velocity `v_off`, and the elapsed hold time `d = t_off − t_on`.
- Decay: the velocity decays to zero over the Decay time, starting at the note-on; the decayed
  level at `t_off` becomes the output velocity [manual]. Decay runs from 10 ms to 60 s and loads
  at 60 s, its longest [dump 12.4.6]. The curve (linear in velocity, in decibels or exponential)
  and the clamp at `d ≥ Decay` (velocity 0 would be a note-off, so the output is presumably
  limited to at least 1) are [measure].
- Release Velocity: sets the balance between the incoming note-on velocity and the note-off
  velocity [manual]. A natural reading is `v_out = (1 − r) × v_dec + r × v_off` with `r` =
  Release Velocity / 100 and `v_dec` the decayed on-velocity [inferred]; at 0 % the release
  velocity is not used [manual]. Whether Decay is applied before or after the balance, or only to
  the note-on side, is [measure]; so is the output at 100 %.
- The 11.1 fix says the velocity was wrong when a note was released after being recorded in a
  loop [source: 3]: the device times Decay from the note-on of the *same* note, including notes
  that began before a loop jump [inferred].

**Key Scale.** Output length is multiplied by a factor that depends on `pitch − C3`, with C3 the
pivot, where C3 is MIDI note 60 in Live's naming [inferred]. Positive Key Scale makes low notes
longer, high notes shorter; negative inverts [manual]. The shape (exponential per octave,
linear, a percentage per semitone) and the largest factor are [measure]; the control runs from
−1 to 1 [dump 12.4.6]. The
control is available only in Note Off mode [manual: it is one of three controls
that only Note Off mode offers].

**Latch.** Both modes replace Gate and Length with the player's own gestures [manual]. The text
of the manual and of the 12.0 release notes together:
- *Note On + Latch.* Triggered notes continue to sound after the keys are released; they end when
  **all keys and the sustain pedal (if connected) are released and a new note-on arrives**
  [manual; source: 2]. So one gesture (any number of notes pressed together or one after the
  other while at least one key or the pedal is down) builds a set of latched notes, and the next
  fresh press ends the whole set [inferred]. Whether the new note-on ends the old notes at the
  same instant it starts, and whether notes pressed while others are still down (before the last
  release) are added to the set, is [measure].
- *Note Off + Latch.* Notes start when all keys and the pedal are released and a new note-off
  arrives [manual; source: 2]. The text is ambiguous: the "new note-off" may be the final release
  itself. Which notes start (those of the gesture, all released together), and when they end
  (at the next such event, as in Note On mode), are [measure]. Release Velocity, Decay and Key
  Scale are deactivated, so the output velocity is presumably the note-on velocity [inferred].
- The device reads the sustain pedal (CC 64) in Latch mode [manual]. Outside Latch mode it does
  not [source: 7, partly: a post says it ignores CC 64]; [measure].

**Held notes.** Not stated by the manual for any mode other than Latch. In Note On mode a held
key does not extend the output past Length × Gate [inferred]. In Note Off mode a note-on with no
note-off yet produces nothing, and does not hang. Switching Trigger Source with notes held, or the
device off: [measure]; see [common.md](common.md) › Switching a device off while notes sound.

**MPE.** Per-note expression goes with the note in Note On mode [inferred]; in Note Off mode the
expression data that arrived while the key was down has nothing to apply to [inferred; measure]. See
[common.md](common.md).

**Latency.** No latency is reported; the delay in Note Off mode is a musical delay, not host
latency [inferred].

## Edge cases

All [measure] unless tagged.

- **Note longer than the output** (Note On mode): the output ends first; the later input
  note-off is consumed.
- **Output longer than the gap to the next note of the same pitch** (a repeated note): overlap,
  retrigger or the earlier note ending at the new note-on.
- **Zero-length and very long output**: shortest Length and Gate; Length at its maximum with
  Gate 200 % (the forum's 120 s trick is a use as an infinite latch [source: 6, partly]).
- **Transport stop / loop jump with output notes sounding:** pending note-offs fire at once or
  at their time? Note Off mode with the clip note ending at the loop end: does the trigger occur?
  Notes held across the loop end in a clip.
- **Tempo change** during a Sync-mode note (end time in beats).
- **Velocity 1 and 127** in Note Off mode with Release Velocity 100 %, Decay at its extremes:
  clamp to 1 – 127; velocity 0 as the result.
- **Pitch extremes** with Key Scale at its extremes (MIDI 0 and 127).
- **Sustain pedal** held: outside Latch, ignored; in Latch, counts as held.
- **Switching Trigger Source or Latch while notes are held or sounding.**
- **Gate or Length automated while a note sounds:** the end time is computed at note-on and
  stays, or follows the new value.
- **Device in a Rack / after another effect that changes pitch:** the pairing of note-offs
  (common.md).

## Measurement plan

Observation: record the device's output on a second MIDI track and read the notes back
([common.md](common.md) › Measurement plan shared by the MIDI effects; arming and recording are
the user's step). The shared cases apply: C1 (switch-off with held notes), C3 (transport stop), C2
(latency), C5 (MPE) and C6 (Rack).

Input clips (120 bpm, 4/4, one bar each unless noted):

- **A.** C3 at beat 1, length 1 beat, velocity 100, release velocity 64 (default). Copies with
  length 1/16 and 2 beats, to see Length against the input length.
- **B.** Notes at pitches 24, 36, 48, 60, 72, 84, 96 (octaves of C), each 1 beat, velocity 100.
- **C.** C3 with velocity 1, 64, 127 and release velocity 1, 64, 127 (nine notes, spaced
  2 beats apart over 4 bars).
- **D.** Held chord C3, E3, G3, starting together, 4 beats long; plus a second chord a bar later.
- **E.** A note held for 8 beats across a clip loop end (loop length 4 beats).

1. **Parameter facts.** Done: the Live 12.4.6 parameter dump and saved set (Controls, `.als`
   import). Still open: which Trigger Source state is Note Off, and which controls the panel
   disables in each mode (the API keeps them all).
2. **Note On timing.** Clip A, Note On, Time mode, Length 100 ms, 500 ms, 1000 ms, 5 s at Gate
   100 %; then Gate 25, 50, 100, 200 % at Length 500 ms: output length against Length × Gate.
   Include a Gate and Length at their minimum.
3. **Sync lengths.** Length at each of the 10 steps in Sync mode, tempo 120 and 90 bpm: output
   length in beats, against the dump's list (0, 1/64 … 1/4); what step 0 (`0`) gives.
4. **Tempo change.** Sync Length 1 beat with tempo automation 60 → 180 across the note.
5. **Note Off timing.** Clip A, Note Off, Length 200 ms: output start (should be at the input
   note-off, beat 2) and end. Clip with input length 1/16 and 2 beats to confirm.
6. **Velocity law.** Clip C, Note Off, Release Velocity 0 %, 50 %, 100 % with Decay at its
   maximum (no decay): output velocity against `v_on`, `v_off`. Then Decay at 100 ms, 500 ms,
   1 s, 2 s with Release Velocity 0 % and the input held 100 ms, 250 ms, 500 ms, 1 s: the decay
   curve, and `d ≥ Decay` clamp. Then both together.
7. **Key Scale.** Clip B, Note Off, Length 500 ms, Gate 100 %, Key Scale at −1, −0.5, 0, 0.5,
   1: output length per pitch, giving the pivot (C3 = 60 expected) and the law.
8. **Note On mode ignores Key Scale / Release Velocity / Decay?** Clip C and B with these set to
   extremes in Note On mode.
9. **Latch.** Clip D, Note On + Latch, then Note Off + Latch: start and end of each output note
   for chords played together, overlapped (note 2 starts before note 1 ends) and in separate
   gestures; add a CC 64 event (clip envelope, value 127 then 0) around the keys.
10. **Retrigger and overlap.** Repeating the same pitch every 1/8 note with Length 500 ms.
11. **Held-note edge cases.** Clip E; transport stop while the output note sounds; device
    switched off during it (common.md case C1).
12. **MPE.** An MPE clip with pitch bend and pressure on one note, Note On and Note Off
    modes (common.md case C5).

## Implementation notes

- A per-block event list in/out plus a scheduler of timestamped output events (note-offs in
  Note On mode; whole notes in Note Off mode). Sample-accurate in seconds; Sync lengths converted
  from beats using the tempo map so a tempo change moves the end.
- Held-note table keyed by (channel, pitch), storing `t_on`, `v_on` and the output note for each
  input note, so the input note-off finds its note (Note Off mode) or is consumed (Note On mode).
  Keep the output note id so the scheduled note-off ends the right instance.
- Latch needs a count of held keys and the CC 64 state, plus a set of latched output notes.
- Velocity maths in Note Off mode: keep the decay as a function of `d`, apply the balance after
  it, round to an integer and clamp to 1 – 127. The exact law is the main unknown.
- Hard to match: Latch edge cases, Key Scale's law, the minimum lengths, retrigger of the same
  pitch.
- **`.als` import.** The device element is `MidiNoteLength` [als 12.4.6]. Parameter elements,
  in stored order [als 12.4.6]: `On`, `Mode` (Trigger Source, bool, false in a fresh device),
  `Latch` (bool), `SyncState` (Sync On, bool), `SyncedLength` (index 0 – 9), `TimeLength`
  (**stored in ms**, 10 – 60000; the API's 0 – 1 is the log taper above), `Gate` (percent,
  1 – 200), `Balance` (Release Velocity, percent, 0 – 100), `DecayTime` (**stored in ms**,
  10 – 60000), `DecayKeyScale` (−1 – 1). The stored ranges are the elements'
  `MidiControllerRange`. No other state is stored.
