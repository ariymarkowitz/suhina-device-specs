# Arpeggiator (manual 30.1)

**Family:** note generation
**Note status:** dump checked

## Summary

Turns the notes held at its input into a rhythmic sequence of single notes (or repeated block
chords) played on a grid of the song tempo or at a free time in milliseconds. The held notes are
ordered by a Style, rotated by an Offset, optionally transposed in several steps (by semitones
or scale degrees), given a Gate length, a groove and a velocity slope that fades towards a
target, and restarted by Retrigger or limited by Repeats. Hold keeps the pattern going after the
keys are released. It is the busiest MIDI effect and the only one with its own clock.

Shared parts (title bar, Scale Awareness, tempo sync, groove, note-off handling, MPE, racks,
latency): [common.md](common.md). History: redesigned in Live 12.0 with Use Current Scale
[source: 2]; the older device had a Transposition Mode of Shift / Major / Minor [source: 3].

**Confidence.** The manual names the controls and describes them loosely; it gives no ranges,
defaults, rate lists or note orders. Ranges, defaults, step lists and displays now come from the
Live 12.4.6 parameter dump (`[dump 12.4.6]`) and stored names from a saved set (`[als 12.4.6]`);
behaviour that is not yet measured stays `[measure]`. The note orders of the styles are given as working hypotheses
(`[inferred]`) because the manual shows them only as pictures; the Measurement plan reads them
back in one recording.

## MIDI flow

```text
held notes ──► ordered list H ──► Style ──► Offset ──► transposed copies ──► step clock ──► note-on / note-off
 (note-ons,     (pitch order or    (base    (rotate)    (Distance, Steps,     (Rate, Groove,   (Gate length,
  note-offs,     play order)       pattern)             Root, Scale)          Retrigger,       velocity slope)
  Hold)                                                                       Repeats)
```

1. **Input.** Note-ons and note-offs of the incoming notes are collected into the held list;
   with Hold on, released notes stay in the list until a new key press replaces them
   [manual: Hold]. The incoming notes themselves are **not** passed on: the device outputs only
   the generated notes [inferred; measure: confirm that nothing of the input reaches the output].
2. **Style** turns the list into an order of notes (a base pattern of N or more steps)
   [manual].
3. **Offset** rotates the base pattern so the start moves by a number of places [manual].
4. **Transposition** repeats the pattern Steps more times, each time shifted by Distance (semitones
   or scale degrees), starting from the original pitch [manual].
5. **Clock.** One step every Rate, on the song's beat grid in Sync mode, with the Groove
   moving steps and Retrigger/Repeats deciding when the pattern restarts or stops [manual].
6. **Output.** Each step is a note-on at the step time with a velocity from the input note
   (shaped by the Velocity slope) and a note-off Gate % of Rate later [manual; inferred].
7. Other messages (CCs, pitch bend, pressure, program change) at the input: pass through
   [inferred; measure, common.md case C7]. MPE: the expression of an input note modulates the
   arpeggio's notes of that root; transposed copies do not get it (Live 11.0), and per-note
   pitch bend is kept in the scale when Use Current Scale is on [source: 2, 3].

## Behaviour

Notation. The held notes sorted by pitch, low to high, are `n0 … n(N-1)`. The pattern base is the
ordered list the Style produces. All times are in beats of the song unless milliseconds are
said. Where the manual is silent the rule is `[inferred]` and has a case in the Measurement
plan.

### Styles: the order of notes for a held chord

The manual gives the names only and shows each pattern as a picture [manual; source: 1, 3]. The
rules below are the usual definitions; the examples use the chord C E G B (MIDI 60 64 67 71;
Live calls 60 "C3") and indices into the pitch-sorted list, and are repeated forever unless the
step count runs out. Every row is `[inferred]` until the Measurement plan's case A1 reads it.

| Style | Index order for N notes | C E G B | C E G |
|---|---|---|---|
| Up | 0, 1, …, N-1 | C E G B | C E G |
| Down | N-1, …, 0 | B G E C | G E C |
| UpDown | zigzag, each turning note played once: 0 … N-1, N-2 … 1, then back to 0 | C E G B G E | C E G E |
| DownUp | the zigzag starting at the top | B G E C E G | G E C E |
| Up & Down | up then down, the extreme notes played twice: 0 … N-1, N-1 … 0 | C E G B B G E C | C E G G E C |
| Down & Up | N-1 … 0, 0 … N-1 | B G E C C E G B | G E C C E G |
| Converge | outside in, alternating lowest and highest: 0, N-1, 1, N-2, … | C B E G | C G E |
| Diverge | inside out; either the reverse of Converge or a walk from the middle note out, see below | G E B C or E G C B | E G C or E C G |
| Con & Diverge | converge, then diverge with the centre not repeated | C B E G E B | C G E G |
| Pinky Up | the highest note ("pinky") between each of the others, which rise from the lowest: 0, N-1, 1, N-1, 2, N-1 … up to N-2, N-1 | C B E B G B | C G E G |
| Pinky UpDown | as Pinky Up, but the other notes zigzag up and down | C B E B G B E B | C G E G |
| Thumb Up | the lowest note ("thumb") between each of the others, which rise: 0, 1, 0, 2, 0, … 0, N-1 | C E C G C B | C E C G |
| Thumb UpDown | as Thumb Up, but the other notes zigzag | C E C G C B C G | C E C G |
| Play Order | the order the notes were pressed | | |
| Chord Trigger | all held notes together on each step (a block chord) [manual] | C+E+G+B | C+E+G |
| Random | a new random note of the held notes on every step [manual] | | |
| Random Other | random, but a note is not repeated until all the other held notes have been used [manual] | | |
| Random Once | one random order, repeated until the held notes change, then a new one [manual] | | |

Points the table leaves open (all `[measure]`):

- **Which of the "&" names doubles the turning notes.** The Live 11 manual lists "UpDown /
  DownUp" and "Up & Down / Down & Up" as two families and does not say how they differ
  [source: 3]. The table assumes the ampersand joins two separate sweeps so the extremes are
  played twice, and the plain name is a continuous zigzag; the opposite assignment is possible.
- **Diverge.** The reverse of Converge ends on the extremes (G E B C for four notes); a walk from
  the middle starts at the lower middle note (E G C B). Even N and odd N may differ.
- **Pinky and Thumb** keep one note as a "pedal" between all the others. The names come from
  playing the pattern by hand (pinky holds the top note, thumb the others) [source: 4]. For one
  held note every style gives that note.
- **Two notes.** Up, Down, Converge, Diverge and the zigzags degenerate; the Measurement plan
  records N = 1, 2, 3 and 4.
- **Pattern length** (the number of steps before it repeats): N for Up and Down, 2N-2 or 2N for
  the zigzags, N for Converge and Diverge, and so on; it decides how Offset, Repeats and the
  transposition cycle interact below.
- **Play Order.** Pressing order, oldest first; the order of notes that arrive on the same
  clock tick (a chord played from a clip) is the order of the events in the clip's note list
  or pitch order [measure]. A note pressed again after release goes to the end [inferred]. It
  is only audible when the notes were pressed in a different order than pitch order [manual].
- **Random styles.** The random numbers are redrawn at each step (Random), per full cycle without
  repeats (Random Other), or once per change of the held notes (Random Once). Whether the pool
  includes the transposed copies (12.0 fixed Steps not using its full range in Random [source: 2]
  suggests it does), what happens with only one note, whether Random Other avoids repeating
  the last note across the cycle boundary, and the pseudo-random source (it is not seeded
  by the song: two plays differ) are open. A Suhina device uses a seeded generator and
  documents that [inferred].

### The step clock

- **Sync mode.** Steps fall on a grid of Rate (in beats) locked to the song time, not to the
  moment the key was pressed [inferred from "Beat retriggering aligned to song position",
  source: 3]. A first note pressed between two grid points waits for the next one; since 12.4 a
  note that arrives within 5 ms after a grid point starts at that point [source: 2]. The
  arpeggio keeps running with the transport stopped [inferred; measure case A5].
- **Free mode.** One step every Rate ms; where the first step lands (at the key press, or on an
  internal clock) is [measure]. Whether the free clock follows tempo changes (it should not) is
  [measure].
- **Groove.** In Sync mode the groove chooser moves steps off the grid like a clip groove; the
  groove's timing, and possibly its velocity, apply [inferred]. Since 12.2 the groove also
  works with Gate between 75 and 100 % [source: 2]. The grid is the groove's Base; the
  Rate must be equal or finer (e.g. a 1/8 groove on 1/16 steps swings the off-steps) [inferred].
  With Global Groove Amount at 0 the steps are straight. In Free mode the groove is likely
  without effect [measure].
- **Step time** `T(k) = grid(k) + groove offset(k)`, with note-off at
  `T(k) + Gate × Rate`. Gate above 100 % makes the note outlive the next note-on. If the next
  step has the same pitch (one held note, Gate > 100 %) the earlier note-off falls after the
  new note-on of that pitch; whether Live shortens the old note to end at the new onset or sends
  an overlapping on/off pair is [measure].
- **Gate and the last note.** If the keys are released (no Hold) while a note is sounding, the
  note continues until its gate end [inferred; measure].

### Hold

- **Hold on:** released notes stay in the pattern. A new key press when no key is held
  *replaces* the pattern with the new note(s). While at least one original key is still held,
  a new key is *added*; pressing a held-pattern note again *removes* it [manual].
- Turning Hold off stops the pattern (the manual suggests briefly turning Hold off to stop it)
  [manual]. If keys are still held at that moment, the pattern continues with them [inferred].
- **Order of notes added to a held pattern.** Appended to the end of the play order, and in
  pitch order for the pitch styles [inferred; measure].
- 11.0.10 fixed a crash from repeatedly adding and removing notes of a held chord with Hold on
  [source: 3]: this is a stress case for the implementation.

### Offset

- The base pattern, for example [a b c] (Up on three notes), is rotated left by Offset places:
  Offset 1 gives [b c a] [manual]. In the manual's picture the notes lie on a circle played
  clockwise and Offset turns the circle counterclockwise by one note [source: 3].
- The rotation is modulo the pattern length [inferred]. Whether the rotation applies to the
  base pattern, to each transposed copy, or to the whole sequence including all Steps, and
  what a negative Offset does (the range is −8 to 8 [dump 12.4.6]); and what happens when the number of notes changes
  while Offset is set are [measure]. Offset also applies to Down and zigzag patterns as a
  rotation of their sequences [inferred].

### Transposition (Distance, Steps, Root, Scale)

- After one full pass through the pattern, the pattern plays again shifted by Distance, and
  so on for Steps shifts; the first pass is unshifted, then k × Distance for k = 1…Steps
  [manual]. With Steps = 0 there is no transposition and Distance is greyed out [source: 2].
  After the last shifted pass the sequence returns to the unshifted pass [inferred; measure:
  whether instead it reverses direction].
- A positive Distance rises, a negative one falls; the pattern starts at its original pitch
  either way [manual].
- **Shift (semitones).** pitch + k × Distance, no wrap; notes that would pass 0 or 127 are
  dropped, wrapped or clipped [measure].
- **Scale-constrained.** With a Root and Scale, or the clip's scale when Use Current Scale
  is on, Distance counts scale degrees: a note moves by k × Distance degrees of the scale
  [manual]. Where the note is outside the scale, the starting degree comes from the nearest scale
  note up or down; the display of Distance in degrees; the number of degrees in an octave for
  scales of 5, 6, 7, 8 notes (the octave wrap) [measure; common.md Scale Awareness].
- **Distance semantic change.** 12.1.5 made the dial bipolar [source: 2]; in 12.4.6 it is
  −24 to +24 st, stored as the semitone count [dump 12.4.6; als 12.4.6]. Earlier the range may
  have been one-sided, so old Sets may store a different range [measure].
- With no clip scale, Use Current Scale on: [measure; common.md].
- **Per-note pitch bend** of incoming MPE notes is transformed so that bent notes stay in
  the scale when scale awareness is on (12.0; fixed for out-of-scale notes in 12.1.10)
  [source: 2].

### Retrigger

- **Off.** The pattern does not restart: it runs with the song grid and the position inside
  the pattern after a new note is [measure: continuing, or from the start when the list was empty].
  A pattern that begins from an empty held list starts at its first element [inferred].
- **Note.** A new key press restarts the pattern: position 0 of the base pattern, transposition
  step 0, Offset applied, the Repeats counter and (with velocity Retrigger on) the velocity
  slope [manual]. Whether the restart is immediate (an extra, off-grid note) or at the next
  step of the grid [measure]; and whether a chord's notes pressed a few ms apart each
  retrigger [measure].
- **Beat.** The pattern restarts each Interval counted from the start of the song (a bar
  or beat fraction), so that every pass begins on the grid regardless of the pattern's length
  [manual: "aligned to song position"]. The interval list runs from 1/16 to 4 in 15 values
  [dump 12.4.6]; that these are bars, so values below a beat exist, is [inferred; measure]. The LED flashes on every retrigger (including Note).
- A retrigger when the previous pattern has not reached its end cuts the pattern: the sounding
  note continues to its gate end and the next note is the first of the new pattern
  [inferred; measure].

### Repeats

- Repeats counts how many times the pattern plays after each trigger; ∞ is endless; 1 or 2 give a
  strum or a short arpeggio [manual]. After the last repeat no notes are produced until a new
  trigger. What counts as a repeat (the base pattern, or the whole pattern with all its
  transposition steps) and what a trigger is (a new key press, a Retrigger, or both) are
  [measure]. With Retrigger Off and Repeats finite, does a new key press start again (it is
  a trigger as an input event) [measure]. Combined with Beat retrigger, Repeats makes pauses
  between arpeggios [manual].

### Velocity slope

- With Velocity on, each output note's velocity moves linearly (or exponentially) from its
  start value towards Target over Decay, measured from the beginning of the pattern (or of
  the last retrigger with Retrigger on); with Target 0 the pattern fades out [manual]. The start
  value is the input note's velocity [inferred]. Whether the slope is linear in velocity or in
  dB, whether it holds at Target after Decay, how a Target above the input velocity behaves
  (a crescendo), whether the clock restarts per key press or per pattern when the velocity
  Retrigger is off, and what velocity 0 does (a note-on of velocity 0 is a note-off; the output
  probably has a floor of 1) are [measure].
- With Velocity off, the velocity of the generated note equals that of its input note
  (the Chord Trigger style: each note's own velocity) [inferred].

### Note-offs of the input

- An input note-off removes the note from the held list (without Hold). The generated notes
  already started keep their own gate length: the output note-offs come from the Gate
  [inferred]. The input velocity 0 note-on is the same as a note-off.
- With Hold on, the input note-off is swallowed (the note stays in the list) [manual]. A
  second press of a held note removes it [manual]; the note-off after that second press must be
  ignored too [inferred].
- Sustain pedal (CC 64): ordinary CC, passed through [inferred]. Whether the pedal acts as a
  Hold is [measure].

### Release velocity and MPE

- The note-offs the device generates carry a release velocity of [measure] (0 or 64 or the
  input's).
- MPE: Slide (CC 74), Pressure and pitch bend of an input note modulate the arpeggiated notes
  of that note; transposed copies get none [source: 3]. 12.1 fixed MPE going wrong when the
  device sits in or after a MIDI Effect Rack and the device no longer sends superfluous MPE events
  [source: 2]. 12.4 fixed the output changing a lot when a Max for Live MIDI effect precedes the
  Arpeggiator [source: 2].

### Latency

Unreported [measure]. In Sync mode the first note waits up to a grid step, which is musical
timing, not device latency [common.md](common.md#latency).

## Edge cases

- **No notes held, Hold off:** silence. **Hold on and empty list:** silence.
- **One held note:** all styles repeat that note; Converge and Diverge likewise [inferred];
  Chord Trigger is just that note.
- **The same pitch pressed twice** (two channels, or a repeated note-on without a note-off):
  one entry in the held list or two [measure].
- **Notes added or removed while running:** the list is re-sorted; the position in the pattern
  is kept as an index, so a change of N can repeat or skip a note [inferred; measure];
  Random Once regenerates [manual].
- **Pitches past 0 / 127** after transposition [measure]. **Velocity 1 and 127** pass; the
  slope's floor [measure].
- **Gate extremes:** at the lowest Gate the notes are as short as the minimum the
  engine allows; above 100 % overlapping. 10.0.6 fixed Gate typed as 100 playing at half rate
  [source: 4]; a regression test for typed values.
- **Very high rates / very low Free ms:** the number of notes per block can exceed the held
  count; every step must be placed at its own sample offset [inferred].
- **Transport.** Stop with notes sounding: the sounding notes are ended [inferred, case C3].
  Start/loop jump/locator: the grid follows the song position; 12.2 fixed notes skipping or
  repeating when the arrangement looped [source: 2]. Tempo change while running: the next step
  time changes [inferred].
- **Device switched off while arpeggiating:** see common.md case C1.
- **Switching Style, Rate Sync/Free, Offset, Steps, Distance, Root or Scale while running:**
  the current note ends normally; the next step uses the new setting [inferred]; whether
  the pattern position resets [measure].
- **Use Current Scale and a clip change:** the scale changes when a new clip starts on the
  track [measure].

## Measurement plan

Method: common.md › Measurement plan, way 1 (record the device's output on a second MIDI
track). One input clip per held-note case, 4 bars, notes written with the Remote Script. Unless
stated otherwise: Rate 1/16 Sync, Gate 50 %, Offset 0, Retrigger Off, Repeats ∞, Steps 0,
Hold off, Velocity off, Groove None, Use Current Scale off. Read, for each output note: start
(beats), length (beats), pitch, velocity, channel.

**A0. Defaults and ranges.** Done: the Live 12.4.6 parameter dump (Controls). Still open: the
display of Distance with Use Current Scale on (degrees or semitones).

**A1. Style order.** Input clips: (a) one note C3; (b) C3 G3; (c) C3 E3 G3; (d) C3 E3 G3 B3;
(e) C3 E3 G3 B3 D4 (five notes), each held 4 bars. Run every Style (18 tracks, each with the
device set to one Style and followed by a recording track; arm all recorders for one take).
Read the first 24 output pitches per run. Fills the table above; settles Diverge and the "&"
names; pattern lengths.
For Play Order: clip (f) the same four notes started in order G3, C3, B3, E3 one 1/16 apart, and
(g) started at the same time.
For the random styles: 64 steps, check no repeat until all used (Random Other), a fixed order
that repeats (Random Once; also change the chord in the middle of the clip to see a new order),
and the distribution of Random over 200 steps (uniform; repeats allowed). Run twice for a
seeded or free random source.

**A2. Rate lists, Gate and the clock.** For every Sync Rate in the list: note starts of a held
single note over 2 bars (interval in beats). Free: 20, 100, 500 ms and the extremes (convert at
120 BPM and 60 BPM to confirm that Free is tempo independent). Gate at its minimum, 25, 50, 75, 100,
150 and the maximum with a single held note: lengths; the overlap of same-pitch notes. First note
timing: a note starting at 0, at +1 ms, +4 ms, +6 ms and +60 ms after a grid point: latency to
the first output (the 5 ms grace period of 12.4).

**A3. Groove.** Apply a known groove (a swing groove with Base 1/8, e.g. one from the Core
Library) with Global Groove Amount 0, 50, 100, 130 %: step offsets, any velocity change, with
Gate 50 % and 90 %. With Free rate. With Rate 1/8 (equal to the Base) and 1/32.

**A4. Hold, Offset, Retrigger, Repeats.**
- Hold: clip with C3 E3 held for 1 bar, then released; then G3 pressed for 1 beat while nothing
  is held; then C3 E3 pressed again with G3 still held; then E3 pressed again (removal). Read the
  output pitch sets over time. Then turn Hold off by device automation or a second clip.
- Offset: Up on four notes, Offset 0, 1, 2, 3, 4, 5, −1 (if allowed); also with Steps 2 and
  with Converge.
- Retrigger: a clip with notes arriving at 0, 1.3 and 2.6 beats (off-grid), Retrigger Off / Note
  / Beat at each Interval value: the output start of each retriggered pattern and position
  within the pattern; the LED is not readable (view only).
- Repeats: Repeats 1, 2, 3, ∞ with Retrigger Off, Note, Beat 1 bar; a base pattern of 4 notes
  with Steps 1: what counts as a repeat.

**A5. Transposition.** Up on C3 E3 G3, Distance +12 / −12 / +7 / +1 st, Steps 0, 1, 2, max;
Distance +1, +2, −1 with C major selected in the Root/Scale choosers, then with Use Current Scale
and a clip scale of D Dorian, pentatonic and Scale Mode off; a note outside the scale. Notes
near 0 and 127 with large Steps. Read the pitch sequence, the wrap/return after the last step,
and the clipping/dropping.

**A6. Velocity.** Input velocity 100 and 20: Velocity on, Target 0 / 64 / 127, Decay minimum /
middle / maximum, Retrigger off and on with Retrigger Beat; read the velocity of each output
note over 16 bars (curve shape, floor, start); Velocity off: output velocity vs input.

**A7. Note-offs and transport.** Playing notes released mid-gate; Hold off; Stop of the

**A8. MPE and scale (common.md C4, C5).** An MPE clip with pitch bend, slide and pressure on

**A9. Racks and C1/C7** from common.md with the Arpeggiator as the device.

## Implementation notes

- **Structure.** Per block: (1) merge the incoming events into the held table (input note id,
  channel, order of arrival, velocity); (2) rebuild the pattern when the table or a control
  changes (a list of (offset in semitones/degrees, source note) steps); (3) a step scheduler
  stepping a *beat-time* clock (`next_step_beat`) against the song position and tempo of the
  block, producing note-ons at sample-accurate offsets, and a pending-note-off list ordered by
  end time; (4) when a note is switched off, a stop or a bypass, flush the pending list.
- **Pattern as data.** Build one array for the pattern: the style gives indices into the
  sorted notes, Offset rotates the array, the transposition expands it into (Steps+1) copies;
  random styles pick from the notes × transpositions at each step. This makes Offset, Repeats
  and Retrigger a single counter over one array.
- **Clock.** Keep the grid in beats (`floor(position / rate) + 1`), handle tempo changes
  within a block, loop jumps and transport stops; in Free mode use a time-based clock. Design in
  beats and seconds, never samples.
- **Random.** Seeded PRNG per device (xorshift or PCG), re-seeded at transport start for
  repeatable renders; Random Other as a shuffle bag; Random Once as a stored permutation.
- **Scale.** Take the scale from the host's clip scale; implement degree arithmetic in one
  helper shared with Chord, Pitch, Random and Scale.
- **MPE.** Carry the per-note expression of an input note onto its output notes with the
  channel of the input; do not replicate it onto transposed copies (Live 11).
- **Groove.** A hook that returns a step offset and velocity change for a step time from the
  host's groove; it may be missing in a first version (UI-only parts can wait: the pattern
  display, previous/next buttons).
- **Prior art.** Textbook arpeggiators; no code is ported. Nothing here needs a licence.
- **`.als` import.** The device element is `MidiArpeggiator` [als 12.4.6]. Parameter elements,
  in stored order, with the API parameter each holds [als 12.4.6]: `On` (Device On, bool),
  `Mode` (Style, index 0 – 17), `PatternOffset` (Offset, −8 – 8), `RepeatCount` (Repeats,
  0 – 16, 0 = ∞), `SyncState` (Sync On, bool), `SyncedRate` (Synced Rate, index 0 – 13),
  `Groove` (index 0 – 3), `FreeRate` (Free Rate, **stored in ms**, 10 – 1000; the API's 0 – 1 is
  the log taper above), `Gate` (percent, 1 – 200), `Retrigger` (Retrigger Mode, index 0 – 2),
  `RetriggerInterval` (index 0 – 14), `Hold` (Hold On, bool), `TransposeMode` (the Scale
  chooser, index 0 – 35, 0 = Chromatic), `TransposeKey` (Root, 0 – 11 from C),
  `TransposeSteps` (0 – 8), `TransposeDistance` (semitones, −24 – 24), `VelocitySwitch`
  (Velocity On, bool), `RetriggerVelocity` (Vel. Retrigger, bool), `VelocityDecay` (**stored in
  ms**, 10 – 60000), `VelocityTarget` (0 – 127), `UseCurrentScale` (bool). The stored ranges are
  the elements' `MidiControllerRange`. Other elements, not parameters: `*RelativePosition`
  values for Offset, Repeats, Retrigger Interval and the two transposition controls
  (−1073741824 in a fresh device), and four compatibility flags (`RandomStepsCompatibilityMode`,
  `GrooveCompatibilityMode`, `PatternResetCompatibilityMode`,
  `StrictNoteOnTimingCompatibilityMode`, all false in a fresh 12.4.6 device; presumably true in
  sets from older versions, to keep their old behaviour [inferred; measure with an older set]).
  Sets saved by Live 11 have Transposition Mode Shift / Major / Minor and a key; the import must
  map them to Root, Scale and the semitone case [source: 3; measure the stored form].
