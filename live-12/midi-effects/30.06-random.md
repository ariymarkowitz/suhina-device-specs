# Random (manual 30.6)

**Family:** note transformation
**Note status:** dump checked, partly measured (MIDI recordings, [Measured](#measured))

## Summary

Random moves the pitch of some incoming notes by a randomly chosen number of semitones (or, with
Use Current Scale, scale degrees), upwards, downwards or both. A Chance control sets how many
notes are touched, Choices and Interval set how many different shifts exist and how far apart
they are, and an alternate mode steps through the shifts in turn instead of drawing them at
random. It is used on repeated notes (drum hits, arpeggios, step-sequenced lines) to add
variation [manual].

History: the device is in the Live 11 manual with the same idea (the Live 10 manual could not be reached); Live 11 called the
spacing control **Scale** (a multiplier, not a musical scale) and had a single Rnd/Alt mode
switch [source: 2]. Live 12.0 renamed Scale to **Interval**, split the mode switch into separate
Random and Alt toggles, added the **Use Current Scale** toggle and made per-note pitch bend follow
the transformed pitch [source: 3]. Live 12.1.10 fixed per-note pitch bend in Random when scale
awareness is on and the incoming note is outside the scale [source: 3].

## MIDI flow

Shared parts: [common.md](common.md) (title bar and Use Current Scale, Scale Awareness,
note-off and MPE handling, racks, latency).

```text
note-on  ─► Chance test ─► pick a shift (Random: draw; Alt: next in cycle) ─► apply Sign ─► new pitch ─► out
              [manual]        [manual]                                         [manual]       │
                                                                                             └─► LED +, 0 or − [manual]
note-off ─► looked up by the note it ends; sent at the pitch its note-on went out at          [measured 12.4.6]
other messages ─► not described by the manual; per-note pitch bend is moved with the note       [source: 3]
```

- Only the pitch of note-ons is changed. Velocity, start and length of the note are unchanged in
  every recorded case [measured 12.4.6].
- The device has no clock, so no tempo, transport or sync dependence and no latency: every output
  note starts where its input note did [measured 12.4.6].
- The random generator is part of the device and is not shared or seeded alike: three instances
  with identical settings on the same clip gave three different sequences [measured 12.4.6].
  Whether a sequence repeats from one playback to the next, or is seeded per transport start, was
  not recorded (one take) [measure].

### Context menu and hidden options

None described. Mode and Sign are stepped API parameters, so automatable [dump 12.4.6].

## Behaviour

### Chance and the shift pool (Random mode, Sign Add)

The manual gives two examples, both with Mode Random, Sign Add, Chance 50 % and a repeated C3
[manual]: Choices 1, Interval 12 gives about half C3 and half C4; Choices 12, Interval 1 gives about half
C3 and the rest anywhere from C#3 up to C4. Recorded from 512 notes of C3 each [measured 12.4.6]:

- The shifts are `Interval × k` for `k = 1 … Choices` (the pool has Choices values and no 0),
  each equally likely: Choices 12 and Interval 1 gave +1 … +12 with 29 – 52 notes each (mean 43);
  Choices 3 gave +1, +2, +3 with 165, 185 and 162 notes; Choices 3 and Interval 2 gave +2, +4, +6 with
  176, 175 and 161; Choices 1 and Interval 1 or 12 gave +1 or +12 for every note.
- At Chance 100 % every note is shifted (reading 1 of the old note: 0 is never drawn).
- Chance is the probability of a shift: the unshifted share was 77, 50 and 23 % at Chance 25, 50
  and 75 %, and the shifted notes were spread over +1 … +12 as before.
- Past 127 the pitch is clamped (below).

### Alt mode

At Chance 100 % the shifts go round in a fixed order [measured 12.4.6]:

- Choices 12, Interval 1: 0, 1, 2, … 11, 0, 1, … (the cycle has Choices values and starts at the
  unshifted pitch, which comes first; C4 is not played, so the manual's "until C4" is loose).
- Choices 2, Interval 2: 0, 2, 0, 2, …; Choices 3, Interval 4: 0, 4, 8, 0, 4, 8, ….
- Sub: 0, −I, −2I, … (Choices 3, Interval 1: 0, −1, −2, 0, −1, −2). Bi: the up cycle then the
  down cycle: 0, 1, 2, 0, −1, −2, 0, 1, 2, ….
- At Chance below 100 % the note takes the next step with the probability Chance and otherwise
  goes out unshifted without advancing the counter: at 50 % the sequence was 0, 1, 2, 3, 4, 0, 0,
  5, 0, 0, 6, 7, 8, 0, 9, 10, … , the steps in order with unshifted notes in between. At 0 %
  every note was unshifted.
- Chords: three simultaneous notes (C, E, G every half beat) came out unshifted in every chord in
  Alt mode at Chance 100 %, Choices 12 and Interval 1, where single notes step through the cycle.
  The reason is not known (one counter per pitch would still have stepped) [measured 12.4.6; a
  further run is needed].
- Not recorded: whether the counter is one for the whole device or one per pitch or channel, and
  whether it resets at a transport start (each playback began at 0).

### Sign

Add moves the pitch up, Sub down, Bi either way [manual]. Sub's pool is the mirror image of
Add's (−I … −Choices × I). Bi draws a sign at random and then a value from the pool: at Choices 12,
Interval 1 the 512 notes gave −12 … −1 and +1 … +12 with 15 – 31 each (about half up, half down,
no 0); at Choices 3, Interval 2 they gave ±2, ±4, ±6 [measured 12.4.6].

### Scale awareness

With Use Current Scale on and a scale on the clip, Choices and Interval count scale degrees
from the input note's own degree, and a note that is not in the scale is first moved to the
nearest scale note, a tie going down — the rule Pitch uses [measured 12.4.6]. In C major with
Choices 3 and Interval 1: C3 gave D, E, F (62, 64, 65), C#3 the same as C3, D3 gave E, F, G
(64, 65, 67); with Interval 2: C3 gave E, G, B (64, 67, 71) and D3 gave F, A, C (65, 69, 72).
In C minor pentatonic with Interval 1, C3 and C#3 gave E♭, F, G (63, 65, 67) and D3 (nearer E♭)
gave F, G, B♭ (65, 67, 70). With Use Current Scale on and no scale on the clip, the shifts
are semitones (C3 gave 61, 62, 63) [measured 12.4.6]. A scale that changes during playback was
not recorded. Which clip supplies the scale is in [common.md](common.md).

### Note-offs

The device keeps the output pitch of every sounding note and ends it at that pitch with the
input note's end [measured 12.4.6]. A held C3 (4 beats) came out at 72 for 4 beats, with Choices
stepped from 12 to 1 by automation while it was held it still ended at its own output pitch
(62, 4 beats), and later notes then took the new pool (+1 only), and with the device off from
beat 3 to 6 of the clip a held note kept its shifted pitch and length (70, 8 beats), notes starting
while the device was off passed unshifted, and notes starting after it was on again were shifted
again [measured 12.4.6]. Retriggers of the same pitch inside a held note were lost from the
recording even in bypass (Live does not keep overlapping notes of equal pitch in a clip), so
which note-off ends which is not known [measure]. Notes on several channels were not recorded.
General handling (MPE, sustain, all-notes-off) is in [common.md](common.md).

### Range limits

The output is limited to MIDI pitch 0 – 127 by clamping: no note is dropped, folded or redrawn
[measured 12.4.6]. With Choices 24 and Interval 12 (Add), input 126 and 127 came out at 127
nearly always (the shifts are 12 … 288) and inputs 0 and 1 at the shift values; with Sub inputs
0 and 1 came out at 0, and 126 and 127 at 126 − k, 127 − k (k = shift); Choices 24 and Interval 1
behaved the same.

### LEDs

The three LEDs flash once per note-on after the decision: + if the output is higher than the
input, 0 if equal, − if lower [manual]. They are a display only and can be left out of the DSP.

## Edge cases

- **Chance 0 %:** every note is unchanged in both modes [measured 12.4.6 for Alt; Random not run].
- **Chance 100 %, Random mode:** every note is shifted; 0 is not in the pool [measured 12.4.6].
- **Choices 1:** one possible shift (Interval) in Random mode, with probability Chance
  [measured 12.4.6]; Alt with Choices 1 was not run.
- **Interval 12:** shifts are whole octaves [measured 12.4.6 for Choices 1 and 24].
- **Chords:** each note of a simultaneous chord is drawn separately in Random mode (the three
  notes of a chord took independent shifts); Alt did not shift the chord at all (see Alt mode)
  [measured 12.4.6].
- **Same pitch twice, overlapping,** transport stop with held notes: not recorded (see Note-offs).
  Pitch past 0 or 127: clamped.
- **Pitch bend, MPE:** per-note pitch bend follows the shifted note (12.0), and out-of-scale
  inputs were fixed in 12.1.10 [source: 3]; not recorded; details in [common.md](common.md).
- **Device off:** passes everything unchanged; the shift of a note held when the device is
  switched off stays [measured 12.4.6].

## Measurement plan

Done: items 1 – 3, 5 (partly), 6, 7 (not the changing scale), 9 and 10 (device off) were recorded on a
clip of 512 notes (not 2000); see [Measured](#measured). Open: 4 (a repeated take), 8.

Everything is read from the MIDI the device emits, so the output must be recorded as MIDI (route
the track to a second MIDI track and record, which needs Live's window; AGENTS.md) or, as a second
choice, played into an instrument with a known pitch response and read from the rendered audio by
pitch detection (the existing harness). MIDI recording is exact and is preferred. The parameter
ranges, defaults, step lists and display text come from the Suhina Probe's dump or the Remote
Script's `get_device_parameters`, and stored values from a saved `.als`.

**Input clip for items 1–4:** 4 bars at 1/16, all C3 (pitch 60), 64 notes per bar, length 1/32
(short, no overlap), velocity 100, repeated over 32 loops (about 2000 notes). Record the output
clip and tabulate shift = output − 60 and the LED state if it can be read.

1. **Pool and distribution, Random mode, Add.** Chance 100 %: Choices 1, 2, 3, 12, 24 with Interval
   1, 2, 12 (a few combinations are enough: 1/1, 3/1, 3/2, 12/1, 1/12, 24/12). Read the set of
   shifts and their frequencies: does 0 occur at Chance 100 %? Are the shifts uniform? Then Chance
   25, 50, 75 % to check that the unchanged share is 1 − Chance.
2. **Sign.** The same at Sub and at Bi: pool, symmetry, share of each sign.
3. **Alt mode.** Chance 100 %, Choices 12 / Interval 1 and Choices 2 / Interval 2, 3 / 4: the
   sequence for 40 notes (first output, cycle length, whether C4 occurs, restart). Then Chance 50 %
   and 0 %: does a failed test advance the counter? Alt with Sub and Bi.
4. **Randomness.** Take the same clip twice, once after stopping and restarting the transport and
   once without: are the sequences identical (seeded at start) or different? Also two instances
   of the device, and the device after a Set reload.
5. **Note-offs.** A clip with overlapping notes of equal and different pitches: C3 held 1 bar with
   C3 retriggered every 1/4 inside it; a chord of three notes with unequal lengths; notes on two
   channels. Compare each output note-on with its output note-off (pitch, time). Change Choices
   between a note-on and its note-off (automate in the clip).
6. **Limits.** Input pitches 0, 1, 126, 127 at Choices 24, Interval 12, Add and Sub: dropped,
   clamped, folded, redrawn.
7. **Scale awareness.** A clip in C major with Use Current Scale on: Choices 3, Interval 1 and 2,
   Chance 100 %, inputs C3, D3 and an out-of-scale C#3; read the shifts. Repeat with a minor
   pentatonic scale, a clip with no scale, and with Use Current Scale on while the clip's scale is
   changed during playback.
8. **Other messages.** Velocity, channel, note length, pitch bend, CC, aftertouch: unchanged?
   Per-note pitch bend with MPE input.
9. **Chords.** Three simultaneous notes, Alt: one step per note or per chord.
10. **Latency and off.** Output timing against input to the tick; device off with notes held.

## Measured

Recorded from Live 12.4.6 (`devices/30.06-random/results/*.json`; runs `random-pool`, `-sign`,
`-alt`, `-repeat`, `-noteoff`, `-limits`, `-scale`, `-chords`; 512 notes of C3 for the pool runs),
laws in Behaviour [measured 12.4.6]:

- Random: shift `Interval × k`, `k` uniform in 1 … Choices, with probability Chance; Sign Sub
  negates, Bi picks the sign at random. Alt: cycle 0, I, … (Choices − 1) × I (down for Sub, up then
  down for Bi), a counter that only advances on a pass of the Chance test.
- Pitch clamped to 0 – 127. Scale mode counts degrees from the nearest scale note (ties down).
- No latency; note length and velocity unchanged; instances are not in step; note-offs follow the
  output pitch; a switched-off device leaves held shifted notes alone.

Not measured: repeatability across playbacks, the unexplained unshifted chords in Alt, the LEDs,
MPE, several channels, a clip scale that changes during playback.

## Implementation notes

- **Structure:** a per-block event pass. A held-note table keyed by (channel, input pitch)
  stores the output pitch (a small stack per key to handle retriggers); note-ons draw the shift
  and push; note-offs pop and send. A generator seeded per instance (Live's instances are not in
  step; the rule across playbacks is [measure]); xorshift or PCG-class generators are fine. Clamp the
  output to 0 – 127.
- **Alt:** a counter in 0 … Choices − 1 (cycle length measured), advanced only on a note that passes
  the Chance test; the shift is `counter × Interval`, negated for Sub, and for Bi up on one cycle
  and down on the next. Alt's behaviour on chords (no shift at all) is unexplained; until a run
  settles it, treat each note alike.
- **Scale:** a function from (input pitch, degrees offset) to output pitch that the scale-aware
  devices share; the clip's scale arrives from the host (see [common.md](common.md)).
- **Parameters to ship:** Chance (0 – 1), Choices (1 – 24), Interval (1 – 24), Mode (2 states),
  Sign (3 states), Use Current Scale [dump 12.4.6].
- **`.als` import.** The device element is `MidiRandom` [als 12.4.6]. Parameter elements, in
  stored order, all as the API shows them [als 12.4.6]: `On`, `Chance` (0 – 1), `Choices`
  (1 – 24), `Scale` (Interval, 1 – 24), `Sign` (index 0 – 2: Add, Sub, Bi), `Alternate` (Mode,
  bool: false = Rnd, true = Alt), `UseCurrentScale` (bool). No other state is stored. Sets saved
  before 12.0 hold the old single Mode switch and a Scale value
  that has to become Interval [inferred from source 3].
