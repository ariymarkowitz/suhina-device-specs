# Velocity (manual 30.8)

**Family:** note transformation
**Note status:** dump checked (manual and public sources only; nothing measured yet)

## Summary

Velocity reshapes the velocity of the notes passing through it. A window of incoming velocities
(Lowest, Range) is stretched onto a window of outgoing velocities (Out Low, Out Hi) along a curve
that Drive and Compand bend, Random adds scatter, and a mode decides what happens to notes whose
velocity lies outside the window: clip them to its edge, drop them, or send a fixed velocity. The
Operation control chooses whether it acts on note-on velocity, on release velocity, or on both
[manual]. Typical uses: keeping a quiet player audible, evening out or exaggerating dynamics,
adding variation to repeated notes, splitting a keyboard by how hard it is played, and inverting
dynamics [manual; source: 6, 7].

History: the Live 11 manual has the same controls and the same three modes [source: 2]. In Live 12
the only listed change is keyboard navigation (Tab goes down each column, then across), in 12.0.5
[source: 3]. The Velocity Shaper of Live 12 is a Max for Live MIDI Tool in the clip view, a
different thing [source: 3].

## MIDI flow

Shared parts: [common.md](common.md) (title bar, note-off and MPE handling, racks, latency).
The device has no Use Current Scale toggle, no clock and (expected) no latency [inferred].

```text
note-on velocity v ─┐                                    Operation = Velocity or Both
                    ├─► window test (Lowest, Range) ─► curve (Drive, Compand) ─► map to Out Low..Out Hi ─► + Random ─► clamp ─► out
note-off release v ─┘      │ outside: Clip / Gate / Fixed                                                            [manual]
  Operation = Rel. Vel. or Both                │ Gate: note blocked, LED flashes [manual]
  (the other message passes unchanged)         │ Fixed: output is Out Hi, whatever v is [manual]
```

- Pitch, channel, timing, CCs, pitch bend and aftertouch are not touched [inferred].
- Operation Velocity changes note-ons only, Rel. Vel. note-off (release) velocities only, Both
  changes both [manual]. Whether the same settings are used for both is [measure] (they are
  the same controls, so presumably yes) [inferred].
- Random is the only random part: one draw per note (per note of a chord, as a tutorial reports
  [source: 6]).

The manual states that Lowest and Out Low at 0 and Range and Out Hi at 127 leave the velocities
essentially unchanged [manual]. The loaded device differs a little: Lowest 1, Range 127, Out Low
1, Out Hi 127, Drive, Compand and Random 0, and Operation Both [dump 12.4.6]. For note-on
velocities (1 – 127) both settings should be the identity; with Operation Both a release velocity
of 0 may become 1 [inferred; measure, item 6]. It is not known whether Out Hi can be set below Out Low; a
tutorial says it can and that it inverts the response [source: 6, 7] (the manual does not mention it).

## Behaviour

### Order of operations (proposed)

For a velocity `v` of 1 … 127, with `lo = Lowest`, `hi = min(127, Lowest + Range)`:

1. **Window.** `v` inside `[lo, hi]` is remapped. Both ends are inclusive: a tutorial uses the
   window as a gate and says a note passes when its velocity is less than or equal to the top
   of the zone [source: 7]; with Lowest 0 and Range 127 even velocity 127 must pass
   [manual]. The exact edge handling at `hi` is [measure].
2. **Normalise.** `x = (v − lo) / (hi − lo)`, in 0 … 1 [inferred].
3. **Curve.** `y = shape(x)` with Drive and Compand (below); `shape` is the identity at 0 and 0.
4. **Output window.** `w = OutLow + y × (OutHi − OutLow)`; with `OutHi < OutLow` the result runs
   downwards (inverted) [source: 6, 7].
5. **Random.** A uniform random amount in about `[−Random, +Random]` is added: the manual's example
   (Out Hi 127, Out Low 60, Random 50) says velocities move up and down by up to 50 and stay
   within 60 – 127 [manual]. Whether the amount is uniform, whether it is added before or after the
   rounding, and whether it is clamped to the output window or reflected at its edges are
   [measure].
6. **Round and clamp** to the integers 1 … 127 (a note-on cannot have velocity 0) [inferred].

Modes for velocities outside `[lo, hi]` [manual]:

- **Clip:** the velocity is held at the nearest edge of the window, so it comes out as Out Low
  (below) or Out Hi (above), with the curve applied to the edge: `x = 0` or `1`.
  Random is applied to those too [inferred].
- **Gate:** the note is not passed on; the LED flashes. The matching note-off must be dropped as
  well, or the receiving instrument sees note-offs without note-ons [inferred].
- **Fixed:** every note gets velocity Out Hi, whatever its own velocity, so there is no curve
  [manual]. Whether Random and the window test still apply, and whether Fixed gates
  notes outside the window, is [measure]; a tutorial says Fixed sets the incoming velocity to Out
  Hi [source: 8].

Two Velocity devices with Gate and complementary windows split notes by velocity (a low chain with
Lowest 0 and Range = the split point, a high chain with Lowest = the split point and Range 127)
[source: 7]; an implementation has to make a note near the boundary fall in exactly one of
them: that is the edge handling of item 3 in the plan.

### Operation, release velocity

With Rel. Vel., the incoming value is the note-off's release velocity; the device remaps it with
the same window, curve, Random and mode [manual; the shared settings are inferred]. Live's own
clips store a release velocity per note (64 by default) [inferred]; a played note's release velocity depends
on the controller and is often 64 or 0. What the window does to a release velocity of 0 (not a
valid 1 … 127 value), and what Gate does to a note-off (the note-on has already passed, so
suppressing the note-off could leave the note sounding), is [measure] (item 6). An Ableton staff
comment in a 2010 forum thread says note-off velocity matters mainly for samplers that react on
the note-off [source: 9], so a wrong release velocity is mostly inaudible with ordinary
instruments.

### Drive and Compand: the curve

Ableton publishes no formula. The manual describes the intent: Drive pushes all the values of the
curve towards the extremes, so that positive Drive makes most notes loud and negative Drive makes
most soft; Compand expands the output values towards the extremes of the curve (positive) or
compresses them towards the middle (negative); both may be used together [manual]. Third-party
descriptions agree: Drive "compresses positive values and expands negative ones", Compand acts
symmetrically around the middle velocities and is the subtler one [source: 6]; at Drive +1, three
chords of unequal velocity come out about equally loud, at −1 only the strongest stays audible
[source: 6]. Compand is described as like Drive but producing two curves, exaggerating the loud
and quiet ends when positive [source: 8].

What can be said about the curve [inferred from the descriptions]:

- It is continuous and monotonic, with `shape(0) = 0` and `shape(1) = 1` for any Drive or Compand
  value (the Out Low and Out Hi settings, not the curve, set the output extremes).
- Drive moves the whole curve above the diagonal (positive) or below it (negative), by an amount
  that grows with |Drive|; at Drive 0 the curve is the diagonal.
- Compand at 0 is the diagonal, and its curve is point-symmetric about the centre
  `(0.5, 0.5)`. One sign gives an S-shaped curve with a steep middle (outputs piled at the
  extremes), the other an inverse S with a flat middle.

Candidate formulas to fit against measurement (none is known to be Live's):

```text
Drive:   y = x ^ g,                g = 2 ^ (−s · d)      d in −1…1, s fitted (power curve above the diagonal for d > 0)
Compand: u = 2x − 1;   y = 0.5 + 0.5 · sign(u) · ln(1 + µ|u|) / ln(1 + µ),     µ = 10 ^ (2 f)   f in 0…1
         (its inverse for the other sign:  |u| = ((1 + µ)^|v| − 1) / µ )
```

The Compand form is a µ-law companding curve centred on the middle of the range, which a Max for
Live author used to rebuild the compressing half of Live's Compand, stating that it was meant to
behave similarly rather than to be exact, with the knob mapped through `µ = 10 ^ (2 f)` as his own
choice [source: 5, known only from a search summary because the post could not be opened]. The same
author had worked out the maths of the Drive curve after a Cycling '74 forum poster said theirs
developed at a different speed from Live's [source: 4]; that part is not known. Both the family of
the curve and the mapping from the knob to its shape are [measure] (item 1), and the order in
which Drive and Compand are applied if they do not commute is [measure] (item 2).

### The display

The display plots the output velocity against the input velocity for the current settings. Its
horizontal axis is the incoming velocity, its vertical axis the outgoing velocity [manual]. At the
default settings it is the diagonal [source: 8]. The Range/Lowest window and the Out Hi/Out Low
window are drawn on the axes [manual]. With positive Random a gray band around the curve shows the
spread [manual]. What is drawn outside the window in Clip and Gate modes, whether the curve is
drawn over the full 0 … 127 input axis or only over the window, and how the band is scaled
(±Random, or only within the output window) are [measure] by looking at the display (screen
only, not MIDI). The display is not needed for the DSP; the curve function is.

## Edge cases

- **Velocity 1 and 127:** both inside the default window and unchanged at the default settings.
- **Lowest = 127, Range = 0 or 1;** `hi = lo`: division by zero in the normalisation; Live's
  result (one velocity in, nothing else) is [measure].
- **Out Hi = Out Low:** a flat curve, all notes the same velocity (Fixed behaviour without the
  mode) [inferred].
- **Out Hi < Out Low:** inversion [source: 6, 7].
- **Random with an output range of one value:** nothing to vary [inferred].
- **Rounding:** how fractions are rounded (nearest or floor) [measure].
- **Gate and the note-off:** see Operation.
- **A change of Operation or Mode while notes are held:** the note-off is processed with the
  settings at the time of the note-off [inferred].
- **Device off with notes held;** transport stop; panic; sustain: [common.md](common.md).
- **MPE:** per-note expression is not touched [inferred].

## Measurement plan

Output must be read as MIDI: route the track to a second MIDI track and record (needs Live's
window; AGENTS.md). Audio rendering through an instrument is not suitable because velocity-to-level
responses are not linear. Ranges, defaults, step lists and display text come from the dump or
`get_device_parameters`, stored values from a saved `.als`.

**Input clip V (velocity sweep):** the same pitch (C3), 127 notes in a row, one per 1/16, length
1/32, velocities 1, 2, …, 127; and a copy with the note-off (release) velocity of each note set to
the same number (the Remote Script's note commands should accept a release velocity; if not, edit
in Live's window). Write both as one clip each.

1. **Curve, Drive.** Defaults except Drive at −1, −0.75, −0.5, −0.25, 0.25, 0.5, 0.75, 1 (the
   display's range [dump 12.4.6]): record clip V, tabulate output against input. Fit the family:
   power, Bézier, exponential, piecewise. Also Out Low 0, Out Hi 127 first, then Out Low 40,
   Out Hi 100 to check that the curve is scaled onto the output window.
2. **Curve, Compand and both.** Compand at the same list, then Drive 0.5 with Compand 0.5, and
   Drive 0.5 with Compand −0.5: do they commute (compare with applying each alone to the other's
   output)?
3. **Window and modes.** Lowest 40, Range 40 (and Lowest 0, Range 80; Lowest 80, Range 127;
   Range 1 and 0) in Clip, Gate and Fixed: output of clip V (which velocities pass; are `lo` and
   `hi` inclusive; what do the outside velocities become). Two Gate devices in a Rack with
   complementary windows at the same boundary: does every note pass exactly once?
4. **Random.** Out Low 60, Out Hi 127, Random 50 (the manual's example), 10, 64 (the top [dump 12.4.6]): a clip of 2000
   notes at constant velocity 100 and one at 60; histogram of the outputs (uniform? width ±Random?
   clamped or reflected at 60 and 127?), repeatability across playbacks and after a
   transport restart. Random with Fixed and with Gate.
5. **Operation.** Velocity, Rel. Vel., Both with clip V and its release-velocity copy: which
   messages change; the same settings applied to both?
6. **Release velocity details.** Notes with release velocity 0, 1, 127, and live-keyboard-style
   note-off at 64; Gate with Rel. Vel.: do the note-ons pass and note-offs vanish (stuck notes)
   or are both dropped?
7. **Extremes.** Out Hi < Out Low (inversion, including with Random and Drive), Out Hi = Out Low,
   Lowest 127, Range 0.
8. **Display.** Screenshots only for the user's own reading: curve and gray band at a few
   settings, to confirm the axes and what the band shows (not part of the MIDI output).
9. **Timing.** Output against input at the tick; device off; parameter changes during held notes.

## Implementation notes

- **Structure:** a per-block pass over note events. Build a 128-entry table `T[v]` from the window,
  curve and output window whenever a parameter changes; a note-on or note-off event looks its
  velocity up, adds Random, rounds and clamps. Gate removes the event; for Gate, a small
  held-note table (channel, pitch) so the note-off of a dropped note is dropped too. No scheduler,
  no latency.
- **Random:** a seeded generator, with a documented rule for when the seed is reset (measured
  repeatability); draw once per event, uniform, in `[−Random, +Random]`.
- **Curve:** implement the fitted formula in continuous form so the display can plot it with the
  same function; keep Drive and Compand as separate stages in the measured order.
- **Parameters to ship:** Lowest, Range, Out Low, Out Hi (integers 0 – 127), Drive, Compand
  (−1 – 1), Random (0 – 64), Operation (3), Mode (3) [dump 12.4.6].
- **`.als` import.** The device element is `MidiVelocity` [als 12.4.6]. Parameter elements, in
  stored order, all as the API shows them [als 12.4.6]: `On`, `Drive` (−1 – 1), `Compand`
  (−1 – 1), `Random` (0 – 64), `Mode` (index 0 – 2: Clip, Gate, Fixed), `Operation` (index 0 – 2:
  Velocity, Rel. Vel., Both), `MaxOut` (Out Hi, 0 – 127), `MinOut` (Out Low, 0 – 127), `Range`
  (0 – 127), `Lowest` (0 – 127). No other state is stored.
